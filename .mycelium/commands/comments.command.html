Commands: comments

Purpose: decide whether each comment in a file earns its place, and delete the ones that do not. The standard it judges against lives in comment-earns-its-place.guide.html, not in this file.
Not a template: like explore.command.html and validate.command.html, this document declares no <template id="…"> and nothing conforms to it. It has commands and no type, which is what the .command.html suffix means.

Why this is not a language rule

Every rule in language.template.html takes text and returns matches. Passive voice, sentence length and a bare number sign each decide from the string alone. Whether a comment deserves to exist decides from the comment against the code beneath it, and no regular expression reads that.

A rule also runs inside validate, which gates the whole corpus and walks every document. A model call per comment makes that gate slow and non-deterministic, and a gate whose verdict moves between runs teaches people to ignore it. So this lives beside validate rather than inside it, and fails on its own.

Why the standard is a guide and not a string in this file

The criteria are rationale. Writing them into a prompt inside this script would be the same mistake the guide itself names: putting a decision somewhere nothing can query. As a language-guide the standard is a document — language show comment-earns-its-place.guide.html prints it, language update edits it, and changing what counts as clutter never means touching this command.

A guide is defined in language.template.html as something stated and not enforced, because it carries no <script>. That is exactly right here. The check that enforces this one is not a function the guide could hold.

The three verdicts

A comment gets keep, cut or promote. Two verdicts would be enough to delete clutter, and would delete the wrong thing. A comment recording a rejected alternative is not clutter and is also not where that rationale belongs, so a checker offering only those two either keeps it in the wrong place or destroys it.

promote is the answer to that. The comment stays exactly where it is, and the command prints the knowledge add line that moves it into the graph. So autofix never destroys rationale: it only ever deletes what all of a comment's own content is already visible in the code.
