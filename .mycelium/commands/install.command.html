Commands: install

installs the packages a rule's own mycelium/importmap script declares, for whichever rule needs one seeding did not already catch
Why this exists beside seeding: seeding installs a rule's declared packages once, the moment it writes a corpus where none exists. A rule added by hand afterward, or one an updated mycelium ships with a dependency the installed version never had, is never asked about again — seeding does not run a second time. This command asks.

Commands

Both this command and seeding gather the same shape — a package name and the version range its rule wants — from the same place, a rule's own mycelium/importmap script, and hand it to the same installPackages in mycelium/utils. Seeding gathers from the files it is about to write; this gathers from whatever the corpus already holds.
