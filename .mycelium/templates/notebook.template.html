Why this template exists

The canon is where thinking crystallises. This is where it stays fluid, and it holds the reasoning that underpins the code before any of it hardens. Prior art somebody read, a rule noticed before a check could hold it, a direction the work bends toward, a remark about how the work itself goes.

Neither the code nor git carries that. A task leaves artefacts everywhere, so writing one down a second time protects nothing, while the reasoning underneath leaves nothing at all. An axiom that cannot say where it came from is the symptom this family answers.

Five types, by where the knowledge came from

A notebook-research comes from someone else, so it holds prior art and external work. A notebook-experiment comes from running something, and it carries the code that ran. The other three divide what arrives from thinking.

A notebook-practice arrives from the ground pushing back while somebody works, so it holds what a tool does when you lean on it and how the work itself goes. A notebook-principle arrives from stepping back over what accumulated, and states a rule that outlives the file that taught it. A notebook-direction arrives from wanting the work somewhere it does not currently go.

Provenance is the axis because it does not move. What an entry is about drifts as a project's vocabulary shifts, and that drift is what left one earlier type doing five jobs across 231 nodes. Where a thought came from stays fixed.

None of the three inward tests names a destination. Sorting entries by what each could be promoted into is what an earlier draft of this family got wrong, and grounding already carries that relation as a link an axiom writes for itself.

Four of the five share one shape, since nothing about their fields differs. The experiment adds the three fields an instrument needs.

What an entry no longer carries

Confidence left. 570 earlier nodes carried it, 60% of them sat on three values, and nothing ever read the field. The canon dropped it from an axiom for the same reason.

Status left with the goals it belonged to. Nothing fluid is pending, and an entry that accretes never reaches a state worth declaring. An intention that does want one belongs in the followup family, which drains rather than accumulates.

Dates leave the filename. An entry accretes, so add has nothing true to prepend, and git already knows when a file first appeared. Deriving that beats maintaining it, which is the same rule the rest of this project follows.

A tag is a name, and sometimes a page

126 earlier entries named a template or a family in their prose and 15 linked to it. So a scheme demanding a path before capture asks for something three weeks of writing never produced, and a tag stays a plain name.

A tag matching an entry of the same name is a link to it, and one matching nothing stays a word until somebody writes that page. Nothing stores the difference, because the name computes it. mycelium notebook tags prints the vocabulary with counts, so a near-duplicate reads as drift and a singleton reads as a typo.

Soft matching costs the check. Renaming a page leaves every tag naming it pointing at nothing, where a path would fail the build. That is the price of a capture costing one word.

An experiment carries its instrument

The old detail field permitted a script from the day it arrived, with no tag restriction, and 574 nodes used it zero times. Every number in that corpus was prose. One entry read The 52% discipline figure was generalised from one night and never re-measured, and the figure stood as fact because nothing could re-run it.

So an experiment holds a question, a script and the reading that script last produced. A behaviour in the canon keeps the check that falsifies it, and this is the same move one rung down. The difference is what disagreement means: a red check says the code broke, and a different reading says the corpus moved.

Writing the document therefore comes before knowing the answer, because running the script is how the answer arrives. Logging after the work competes with the work and loses, which is the shape of every capture failure this project has recorded. Here nothing remains to do afterward.

The script type is mycelium/experiment. The prefix already means Node-only and possibly TypeScript, and the second word keeps a runner from confusing a probe with a check. mycelium notebook run runs one on request, and validate never does. A probe that fails the build is a check with worse manners.
