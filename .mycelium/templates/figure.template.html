Template: figure-graph

a diagram that stays a document, with nodes and edges as elements a reader can read straight out of the markup while a stylesheet decides the look inside whatever document draws one, since a figure illustrates its host rather than standing alone the two forms this replaced, and what it still cannot do
Behaviour: ./figure.element.js, a classic script that registers the elements and draws the connectors
Styling: ./figure.template.css, plus the shared ../theme.css

Why this template exists

Two forms of diagram went into the repl report and neither is right. Markup with every box placed by hand looked better and nobody could read it back, because its meaning lived in coordinates rather than in a list of nodes and edges. Mermaid reads back and gives up the styling.

The split between them is not really styling. It is whether the picture is still a document once you have it.

What this form buys that mermaid cannot

A node is a real element, so it can hold anything markup can hold. A box in a diagram can link to the source file it names, or to the node arguing about it. A mermaid node is a string and a dead end.

An edge names its two ends, so an audit can check that both resolve. Mistype a name in mermaid and it invents a node, rendering a diagram that looks right and lies. That failure mode is the one this project cares about most, and closing it is most of the reason to build anything here.

A cell is structure, a pixel is not

A node declares which row and column it occupies and CSS grid places it. That is a coordinate, and it is not the kind that rots. 3,1 means the same thing at any font size, any width and any theme, because the browser works out where that lands every time it draws.

Hand-placed markup failed for a different reason. Its numbers were pixels, so a person had to keep them true, and they stopped being true the moment anything moved. The problem was never that numbers existed.

The connectors carry no numbers at all. They come from measuring the real layout after the browser has done it, so nothing about the geometry reaches the file, not even generated.

Those measurements are relative to the figure's padding box. The overlay the wires go into sits inset: 0 inside the border, and a label is positioned the same way, so both land against the padding box while getBoundingClientRect answers for the border box. Measuring against the wrong one drew every wire one border-width away from the box it had just measured.

Why a classic script, with no mycelium type

Every script type this project invented keeps the browser from running the script. mycelium/command, mycelium/rule and mycelium/audit all rely on the browser skipping an unknown type. An element script is the first one that has to run in the browser, so it carries no type at all.

It also cannot be a module. A document here opens over file://, module scripts are CORS-checked, and that origin cannot satisfy the check — the same constraint the spec that deleted the shared runtime describes.

That reads like a workaround and is not one. customElements is a global registry, so registering an element is a global side effect whichever way the script arrives. There is no module-scoped version of this to give up.

Shape

<figure-graph data-columns="3">
  <figure-node id="system" data-at="1,1">
    <a href="../../src/core.ts">createFileUrlSystem</a>
  </figure-node>
  <figure-node id="blob" data-at="2,1">createFileUrl</figure-node>
  <figure-edge from="system" to="blob">js · ts</figure-edge>
</figure-graph>

data-at is row,column, both counting from one. The attribute constraints on those placeholders are the reserved-word form the schema grew today: a value is a pattern the instance must match, so a figure declaring data-at="middle" fails validation rather than rendering somewhere surprising.

What the schema checks, and what still escapes it

repeatable says a child may appear many times, and every occurrence meets the same checks. conforms-to points a placeholder at the type its content follows, so a graph carries its nodes and edges into validation without each one declaring conformance of its own. A figure with twelve nodes now has twelve placements checked.

None of it reaches a real figure yet, because no figure-graph in this repository declares data-conforms-to at all. A figure lives inside a report or a design document rather than being one, and an instance inside a host is a question this family opened and has not closed. Until it does, the three audits below are the only thing reading a figure.

Two claims this section used to make were wrong, and measuring the corpus corrected both. Plan documents never lost anything this way, because every task, step and check carries its own conformance and meets the validator on its own. And the first child of a kind was not the one that got checked here: no figure was checked at all.

Two kinds of column

data-columns names each column in order, and a column is either a node column or an edge column: data-columns="edge node node node node". A bare count still reads as that many node columns.

An edge column carries no boxes. A back edge runs down the middle of one, and its label sits there as an ordinary grid item, so the grid sizes that column to whatever the label needs.

That is the point of making it a column rather than a margin. Every earlier version positioned the label itself, which made the label's width something this code had to worry about, and a long enough one always reached past the figure. A grid column has a width the grid manages, so no length of text can.

data-at counts node columns only, so reserving an edge column never renumbers what a figure already declared.

A back edge says so, rather than being noticed

An edge that runs against the flow carries data-back. It is the only edge that carries anything, since a forward edge is the ordinary case and says nothing.

The element used to work this out by comparing box positions while drawing. That let a rearrangement restyle an edge with nothing in the document changing, and an inference from measured state always has a wrong answer available to it. The declaration replaces the measurement, and the audit below checks the declaration against the rows, so a wrong one fails the build rather than rendering.

Declaring it in the shape needed the optional marker, since every other attribute a placeholder names is one an instance must carry. data-back="?" is the whole use of that marker so far.

Edges into one box land at points of their own

Several edges reaching the same box share a lane, and that stays: giving each its own lane made three edges into one box arrive as three near-parallel lines. Sharing the drop as well is what went wrong. The lines became one before they landed, so a reader could not count them, and every label anchored to that one drop and stacked on top of itself.

They now land at separate points along the target's top edge, ordered by where each line comes from so spreading them never makes two cross on the way in.

How far apart depends on the labels rather than on a fixed distance. A chip masks the line behind it, which is the point for the line it names and wrong for anyone else's: a covered drop reads as an edge that stops in mid-air. A chip is centred on its own landing, so half of it is what reaches towards the next one, and the landings sit at least that far apart. A box too narrow for that caps the spread instead.

An edge inside one row

Two boxes in the same row are peers, and an edge between them travels sideways rather than down. It runs straight across the column gap, from one box's facing side to the other's, with no elbow and no lane.

The element works this out from data-at rather than from an attribute on the edge. That is not the inference data-back replaced: that one compared measured boxes, and this reads two numbers the figure already wrote down. Moving a node to another row edits the document, so nothing can shift under a peer edge without the file changing too.

A peer edge crosses no gap between rows, so assignLanes leaves it alone. Passing one through there worked a lane out from a negative gap, which turned the wire back through the boxes it joined.

Nothing steers it, so a box standing between its two ends is a box the line goes through. The audit below rejects that. Emptiness rather than adjacency is the test: columns one and three may join, as long as column two holds nothing in that row.

Its label goes in the space above its row, which no other label does. Two neighbours leave only the column gap to run in, around twenty pixels, and a chip is wider than that. Sitting on the line, the label covered the whole edge including the arrowhead, so the picture stopped saying which way the relation ran.

Where a label may go

Every label lives in the gap its own edge crosses, and never over a box. A gap between two rows holds no boxes at any width, so a label kept inside one cannot cover a name the figure exists to show. A peer edge crosses no gap, so its label takes the space above its row instead.

A label also stays inside the figure. A chip is centred on its anchor, so half of it reaches further out than the anchor does, and a long one in the first or last column hung out through the border.

Labels that would cover each other share the height of their gap. Only labels whose widths overlap count as competing: two in different columns of one gap keep the height their own edges gave them. The run is arranged in one pass rather than one label at a time, because nudging each away from the last let the first claim the spot nearest its own edge and leave the second nowhere legal, in a gap that had room for both.

A gap fits two labels. A third has to share, and the three then overlap each other while all staying off the boxes. Covering a box is the failure worth preventing; crowding is a figure asking for more labels than it has room for.

The audits

Three checks. Every edge points at a node that exists in the same figure, every edge runs the direction it claims, and a peer edge reaches its neighbour without crossing a box.

What this pass does not do

No layout engine. A node says which cell it sits in, and a figure whose shape does not suit a grid has no answer here yet. The repl diagram suits one, which is why it is the subject.

No routing. A connector runs from one box to another as a straight line with an elbow, and two connectors crossing stay crossed. Two edges that share no box no longer share a lane, so they cross rather than meeting, but nothing steers either of them around the other.

No authoring command. Writing a figure means writing the markup, which is the state knowledge and language both started in.
