Two comments carry their own verdict. A comment opening with WIP is the author saying out loud that it is a working note, and a doc comment on an export is not documentation about the code but the code's own output, since the roster prints it.

Asking a model about either is asking the wrong question. On the first it would let a model overrule the author. A comment recording a rejected alternative is the most expensive thing in a file to lose, because nothing anywhere else records it. A comment that repeats the code costs a reader a few seconds. Those two are not symmetric, so the command treats them differently.

That asymmetry is why three verdicts exist rather than two. A checker offering only keep and cut either leaves rationale in a comment, where nothing can query it, or destroys it.

Moving it stays a person's job. The command cannot write the decision node's own content, so the most it can do is print the line that starts the move and name the comment it came from. A promotion is therefore an offer and not a finding, which is why a file full of them still exits zero.

Three ways in, and one of them writes. The check command reports, autofix with --diff previews, and autofix alone applies. The person picked which one to run, and that choice is the whole permission the command holds.

A gate that repairs what it measures reports nothing, which is why this project splits check from autofix wherever it has both. The same split gives a hook something to run: a command that fixed as it looked would leave a person nothing to review.

 where the three ways in came from a gate that edits what it measures A fix removes exactly what the report named, and leaves the rest of the file alone.

The report is the contract. Anything else the fix changes is damage nobody approved, and it lands in a file the person had no reason to reread.

The edges are where this goes wrong, because the range a comment occupies is not the range a person would delete. A comment alone on its line takes the line with it; one trailing code takes only itself and the spaces before it. Widening both ends the same way joined two lines into one, and the tests caught it only because this axiom says the fix touches nothing it did not report.

 a fix people cannot trust is one they run once A comment answers to the code it introduces and to every other comment in the file.

Whether a comment earns its place is not a property of the comment. It depends on what the code beneath already says, which is why no regular expression can decide it and why a model reads the two together.

The file is the second half of the context, and the easier half to lose. Three comments that each look defensible alone can be one point made three times, and only a reader holding all of them at once can say so. Splitting a file across calls hides exactly that.

Both halves are bounded on purpose. Twelve lines covers a signature and the start of a body, and the whole file goes in one call rather than one per comment, so the judgment stays affordable while keeping what it needs.
