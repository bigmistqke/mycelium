Add mycelium notebook show <entry>, following language show wherever the two families agree. It prints the path, the type and title, then every field the entry carries, each under a lowercase label and indented by two spaces. Fields print through textContent rather than innerHTML, which is the whole point: a reader wants the detail's wording, not its paragraph tags.

Resolution stays loose the way language's does. <entry> takes a bare slug, a whole filename, or a path pasted straight out of list, and a slug naming more than one type reports every match instead of choosing. Writing stays strict, so update, link and del still demand a whole filename — a wrong guess there edits the wrong entry, where a wrong guess here costs one more command.

Two fields print differently from the rest, and both differences follow the notebook's own shape. A prompt repeats and holds somebody's exact words, so each one prints separately rather than running together. An experiment's script prints verbatim under instrument, for the reason 2026-08-10-experiment-shows-its-instrument.spec.html already gives: the script is the claim, and a description of it is a second copy that drifts.

Edges print last, with their labels. list edges prints the relation and the target across the whole corpus and drops the label, so the one place a reader learns what an edge means is the file. This command becomes that place, which makes it the only way to read an edge's reasoning without opening markup.

Incoming edges stay out. A reader wanting them wants a neighbourhood view, which is a different command answering a different question, and folding it in here makes show scan the whole corpus to print one file. language show prints outgoing edges only and this follows it.

No filter joins list, and no search command arrives. Both are worth weighing separately, and neither belongs to the gap this closes.
