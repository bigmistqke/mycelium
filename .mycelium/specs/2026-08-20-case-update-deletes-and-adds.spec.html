notebook experiment case update: delete and add as one honest command implemented 2026-08-20

An earlier followup, now done, named the gap: changing a case's script means running notebook experiment case del and then notebook experiment case add, and remembering both is the whole burden. Nothing enforced the order, and nothing stopped a session from running the first and forgetting the second, leaving an experiment with one fewer case than intended.

The two-command shape came from a real constraint, stated in this file's own doc comment: a case is its script, so a changed script is a different case, and the readings under the old one measured something nobody asks about any more. That constraint does not require two commands, only that the old case's identity end before the new one's begins.

update deletes and adds, and prints both

notebook experiment case update <file>#<id> --script "…" | --script - [--lens "…"] [--id <slug>] [--browser] resolves the case the address names, prints every reading and conclusion it is about to take with it — the same lines case del already prints — removes it, then builds the replacement through the same attachCase helper case add uses. A shared announceDrop function now backs both commands, so the two can never print the loss differently.

--lens and --id default to the case being replaced

Passing only --script changes nothing else about the case: its lens, its id and whether it runs in a browser all carry over from the case it replaces. Passing --lens or --id renames it on the way back in, the same as passing them to a fresh case add would. The id still defaults from the lens whenever nobody passes either flag, through the same slugFor logic add already uses.

update runs the new case immediately

Once the replacement validates and the document commits to disk, update runs it through the same readCase path case add uses, recording a first reading under the new case the same way a freshly added one gets one. Nothing about running a case changes; only how a changed script gets there does.

  • case del stays as its own command. Dropping a case with nothing to replace it is a different intention from replacing one, and folding both into a single command would make an ordinary delete carry an unused --script flag.
