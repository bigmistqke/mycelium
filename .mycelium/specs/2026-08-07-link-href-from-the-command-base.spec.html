An href computed from the base the command actually uses implemented 2026-08-07

src/run.ts builds an href for every invocation carrying two positional arguments. It resolves both names against docs/ and prefixes ./ to the result. Each link command resolves its own arguments against a subdirectory instead: knowledge/ for one family, language/terms/ or language/rules/ for another.

Two bases, one answer. The href comes out right only when both files sit in the same directory, because there the two mistakes cancel.

One command reproduces the failure:

mycelium language link drift.term.html no-outside-references.rule.html --rel supports

  writes href="./no-outside-references.rule.html" into language/terms/
  the rule lives in language/rules/

The every-link-resolves audit catches the broken href, so no commit carries one. The command still writes it and says nothing, so a person learns what the command did by reading an audit.

The same arithmetic puts one existing edge out of reach. 2026-07-23-template-series-built.outcome.html points at ../templates/knowledge.template.html, which a person wrote by hand. unlink computes the same wrong href, so it deletes whatever link just wrote and never finds that edge. Retargeting it is a prerequisite for closing the relation vocabulary, so this defect blocks that work.

The engine cannot know where a family keeps its files, so it should stop guessing. The command knows already, since it resolves the path before it reads or writes anything. Hand the command a function and let it pass both paths in.

href(from: string, to: string): string

Each argument names a file from the docs root, the same vocabulary fs.get and fs.create take. The function returns the relative href from the first file's directory to the second. It joins cli beside validate, readStdin and parseHTML, because it belongs to the engine rather than to any one document.

a.setAttribute('href', cli.href(pathFor(args._[0]), pathFor(args._[1])))

The leading dot, only where it belongs

The old line prefixed ./ unconditionally, which turns a climb out of the directory into ./../templates/knowledge.template.html. Hand-authored edges write ../templates/knowledge.template.html, and the two strings differ, so an upsert appends a duplicate and unlink misses. The function adds the prefix only to a path starting with a name.

What goes away

The precomputation in src/run.ts disappears entirely. It fired on argument count alone, so any command taking two positional arguments collected an href whether or not it wanted one. Four commands read args.href today, link and unlink in two families, and each one calls the function instead.

Closing the relation vocabulary. This spec brings the two unlisted edges within reach of the CLI; deciding which relation each one means carries its own judgment and waits for its own change.

How knowledge generate reads an edge, which takes the basename of an href and prefixes knowledge/. An edge leaving the directory confuses it, and always has.

Every other command's argument handling. Nothing changes about the paths a command accepts or the place it writes.

Whether the function should check that both files exist. Every caller calls fs.get on both already, which throws on a missing file, so a second check would only move the error message.

Whether the engine should hold a resolver for a family spanning three directories. language keeps pathFor and resolveEntry inside its own template, and nothing outside that template needs them.
