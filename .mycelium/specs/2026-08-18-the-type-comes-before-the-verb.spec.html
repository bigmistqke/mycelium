A command specific to one type names that type before its verb approved 2026-08-18

Every family here takes the type as an argument to a verb. A reader writes canon add axiom, language add term, plan add doc and notebook add principle, so one command builds three or five different things and its flags mean different things depending on which. The notebook's own help says a flag is meaningless on the other two, which is an apology printed where a contract should be.

That overloading costs documentation the corpus can count. One command serving five types carries a hundred and twenty-seven lines of help against a median of twenty-three across the whole command line. A reader wanting one type reads all five, and an author adding a sixth edits prose belonging to the other five.

It also leaves nowhere for a type that carries machinery of its own. An experiment runs, holds cases and takes conclusions, and none of that belongs to a principle. Hanging those verbs off the family put a case in the same positional slot as a provenance, which made the sentence describing that slot false.

A command specific to one type names that type first, and its verb follows. notebook principle add, canon axiom add, language term add, plan doc add. The type stops being an argument and becomes the thing the command belongs to, so each command documents one shape and takes only the flags that shape declares.

A family declaring one type names none, because there is nothing to choose between. spec add and followup add stay exactly as they are, and spec spec add would say the same word twice.

A command working across every type of a family stays where it is. notebook update, del, link, list and show take a file, and the file already says which type it holds, so naming it again would be the second copy this project removes everywhere else. The type appears when nothing else can supply it, which is exactly when a command creates something.

A type carrying its own machinery gets it under the same name. An experiment runs and a case is added, dropped and concluded, so those verbs sit under notebook experiment and notebook case rather than crowding the family. That also settles a name the language reserves: a case appears as an argument the shell passes, never as an identifier the source declares.

This narrows a-declaration-is-the-whole-contract. If what a template declares is the whole contract, then a command asking for something the declaration does not say is outside it, and a flag meaningless for the type under construction is exactly that. The behaviour is the checkable half: no authoring command takes a type as an argument.

Nothing lands halfway. Four families change together, because a convention holding in three of them is a convention somebody has to remember rather than a rule they can rely on, and a check reporting the fourth as a standing finding is the gate people ignore.

The figure family gains nothing and changes nothing. It declares types that no command authors, since a node and an edge get written into the document that draws them, so a rule about which command builds which type says nothing about it.
