A path command moves a file and rewrites every reference to it implemented 2026-08-20

Nothing in this project can move a file. Every cross-reference in the corpus is a relative path written by hand — a stylesheet <link href>, a data-conforms-to, a <script src>, an ordinary <a href> citation, a relative import inside a script — so moving one file today means finding and hand-editing every document that names it, and missing one leaves a dead link every-link-resolves only catches on the next validate.

This blocks reorganizing .mycelium/templates/, currently 31 files flat, into per-family directories: that move touches a large, unknown number of documents across the whole corpus, and doing it by hand is exactly the kind of mechanical, error-prone edit this project's own tooling exists to replace.

mycelium path move <from> <to>, a protocol-only command in the same family as explore and validate — reading only generic signals (href, src, data-conforms-to, a script's own import specifiers), never a specific family's field names, so it needs no changes when a new content family joins the corpus.

It walks every .html file in the corpus once, the same crawl validate already runs, looking for anything resolving to <from>: a stylesheet link, a data-conforms-to (the path half, its #fragment left untouched), a script src, an ordinary <a href>, and a relative import/ from specifier inside an embedded script. This is the same TypeScript-AST technique localReferences in src/run.js already uses to find a seeded document's own dependencies, run here in reverse.

Each match gets rewritten to a fresh relative path from that referencing document to <to>, since a move can change relative distance as well as name. Edits splice into the original bytes at the attribute or specifier's own source location, the way repointOutwardLinks already rewrites a seeded document's outward links — everything else in a touched file survives exactly as its author wrote it.

package.json's own exports map gets the same treatment when one of its values matches <from> exactly, since that is a path reference too, just written in JSON rather than HTML. The file moves last, once every reference to its old path has already been rewritten.

Printed output names every file it touched and how — the same style autofix already reports sorted fields in. Running validate afterward is how a run confirms nothing broke: this command does not validate on its own behalf.

No directory moves — one file per invocation, so a reorganization script calls this once per file rather than the tool inventing its own batch semantics. No rewriting of bare mycelium/* specifiers inside a script: those already resolve through package.json's exports map regardless of where the target file sits, and that map is what this command updates instead. No touching src/run.js's own family-root convention (templates/${family}.template.html in seedPaths) — a small, fixed, engine-known set, not a generic corpus reference, so moving a family's own template into a new directory still needs that one line updated by hand as part of the reorganization that calls for it.
