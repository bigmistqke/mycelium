A host declares what it is, instead of following a meta-block convention approved 2026-08-18

Every host in this corpus opens with a block of bolded labels describing itself, and nothing checks any of it. Across eleven hosts that block uses sixteen distinct labels for roughly six concepts. Four of them name the types a host declares — Node types, Node type, Types and Instances — and two more name the absence of any, as Not a template and Not a node type.

The drift runs deeper than wording. Two hosts describe their family as the shape a document takes when written as a v4 node, naming a corpus that was deleted, so a reader following that description reaches nothing. The canon carries no purpose at all, which makes the newest family and the one holding what the project claims to be true the one family that never says what it is for. Four of the labels also say node, a word this project's own dictionary defines as a document in a knowledge graph that no longer exists.

None of this can fail a build, because a bolded label inside a div is prose. The corpus checks a link, a field and a citation, and this block is none of them. A convention holds only as long as whoever arrives next copies the file they happened to open.

The template family gains a type, and every host conforms to it. template.template.html declares <template id="template-host">, so the file defining the schema vocabulary now also defines what a host says about itself. A host writes one <template-host> element carrying three fields, and the ordinary validator checks its shape the way it checks every other instance.

Only three things earn a field, and each one resists derivation. template-purpose is required and says what the family is for, in prose a newcomer can read. template-files says where instances live, which no engine can compute because a-family-owns-its-paths gives that decision to the family. template-design links the spec that designed the family, and nothing derives a document's ancestry.

Everything a reader could compute stays computed. The types a host declares already sit in its own <template id> elements, its commands already carry doc comments the roster reads, and its stylesheet already appears in the head of every instance. Restating any of those in a field would create the second copy derive-do-not-maintain forbids, which is how four labels came to name one concept in the first place.

Presence needs an audit rather than a required attribute, and the reason is structural. The generic validator checks the shape of an element it finds, and a document holding no conforming element is not an instance, so every per-document check skips it on the line that looks the root up. Absence across a population is what an audit expresses, which is why grounded and exhaustive are audits too. The new one is every-host-says-what-it-is.

One existing audit needs its exemption widened. nothing-outside-the-type already passes over a document declaring template[id], on the stated ground that such a document is documentation about the type it declares. A command host declares commands and no type, so without the same exemption its heading and its prose would read as content sitting outside the new element. The condition widens to cover a document declaring either, which is the rationale it already carries applied to the other kind of host.

The editorial labels stay as prose. Sibling of, Styling, Why a document at all and the rest address whoever maintains the file rather than whoever meets the family, and giving each one a field would structure the part nobody needed structured. A host keeps writing them in its body, where documentation about a type belongs.

The command that reads these fields is a separate piece of work. This spec puts the field in place and checks it; what prints it comes after, and its name is still open.
