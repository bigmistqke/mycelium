An agent meets this corpus from the code, not from a list. It opens a source file to do a task, and the entry worth reading is the one explaining why that file looks the way it does. The count says almost nothing carries that address: a handful of entries name a source file at all, and the rest describe the project without ever saying which part.

The followup family already solved this, and solved it the other way round. Its required --at takes a repository path, so an item waits in front of whoever next opens that file, and nobody reads a list to find it. The notebook has no equivalent, so an entry waits for somebody to guess its filename.

The inward count dwarfs the outward one, which reads two ways and the script cannot separate them. A corpus this self-referential either thinks carefully about its own material or talks mostly to itself. Both look identical from here, and a reader has to open the entries to tell.
