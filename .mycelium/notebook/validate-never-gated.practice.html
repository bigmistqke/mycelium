validate reported failures and exited 0, so no audit has ever gated anything

src/validate.ts counted failures, printed them in red, and returned exit code 0 regardless. There was no process.exit and no exitCode assignment anywhere in the file. Found while running task-3-step-3, which expects a failing validate: the check reported "command succeeded, expected failure" while the same run printed 221 checked, 2 fail.

This refutes a claim the project had written down. CLAUDE.md states that orphans-except-goal is checked "for real" and is "an automated gate now, not just a judgment call." It was never a gate. Every audit written here has been advisory, including the two that predate today, for their entire existence.

A check that reports without signalling is indistinguishable from no check to anything downstream — CI, a pre-commit hook, a plan-check, or a script. It is visible only to a human who happens to read the output, which is exactly the discipline-not-protocol failure this project's founding result was about. The audits were the protocol, and the protocol had no teeth.

It would have silently invalidated the current plan. The decision to make audits fail the build assumed failing was possible. task-6-step-3 — the terminal check of the whole pass, asserting the graph is green with both audits live — would have passed while 52 nodes still violated them. The plan would have reported success on the strength of a command that cannot fail.

Generalisation worth keeping: a gate has two halves, the detection and the signal, and the second is the one nobody tests because the first is the interesting part to write. Any check should be verified by making it fail on purpose at least once. Neither audit here had ever been observed failing — the graph satisfied both until this session added a node that broke one.
