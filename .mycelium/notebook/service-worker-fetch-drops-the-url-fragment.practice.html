A service worker's fetch event never carries the request URL's fragment service-worker but that's a nodejs runtime, i'm talking about a browser runtime that somehow does some fancy stuff with imports. it could be a service worker

While weighing a browser-side counterpart to src/script-hooks.ts — that hook lets a Node import address one <script> inside an .html document with a path.html#locator specifier — the natural instinct was to mirror the same addressing in a service worker intercepting module fetches in a browser.

That does not carry over. A URL's fragment is stripped before the network request is constructed: Request.url, and so FetchEvent.request.url, never carries a #fragment, because a fragment is a client-side-only addressing concept that is never sent over the wire. A service worker intercepting ./lib.html#nimble-html and ./lib.html#other-script sees the same request either way.

A browser-side version of the same idea would have to move the locator into the path or the query string instead — a real asymmetry against the Node hook's addressing, not a detail to smooth over.
