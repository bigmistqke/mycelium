The three checks all run downward, and the one that closes the loop is missing

The derivation design proposes three checks, and all three ask the same direction of question: does an axiom reach a behaviour, does a behaviour reach a test, does every required behaviour have a test citing it. Each one starts from a declaration in a document and looks for the code underneath.

Nothing checks the reverse: every test cites a behaviour. A test that cites nothing is a claim about the system that no specification makes. Under ordinary practice that is an untidy comment. Under the reading that findings travel upward, it is the finding itself — someone knew something about the system and there was nowhere above to put it.

The pair is what closes the loop. The exhaustive check catches specification the code has not caught up to. Its inverse catches code that knows things the specification does not.

Two other things the same reading brings up. Nothing in the design distinguishes an axiom someone committed to from one inferred by reading existing code, and the inferred one is the likelier misreading — knowledge nodes carry a confidence field for exactly this. And a conflict between two axioms has somewhere to live already, since contradicts is one of the six edge labels and knowledge recover prints contested claims; what is missing is anything that finds one, which is the same judgement the design put out of scope as the entailed check.
