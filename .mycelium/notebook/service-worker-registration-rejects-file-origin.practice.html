Registering a service worker throws on a file:// page, no matter what the worker contains service-worker none of that holds for a generated HTML file someone copies, emails, or opens via file:// -> except if that file contains the service worker?

A file:// URL serializes to an opaque origin — "null" — and navigator.serviceWorker.register() requires a non-opaque, potentially-trustworthy origin. It throws at the registration call itself, before the browser looks at what the worker's script contains. Inlining the worker's own source into the page that registers it does not change this: the check is on the page's origin, not on where the worker's code came from.

This matters here because graph-page.ts's templateFile() exists specifically to keep a generated page openable after somebody moves it — "inlined rather than linked, so a page somebody moves still draws". A service-worker-based approach to serving code into a generated page can only ever apply to pages served over a real origin, such as graph-serve.ts's --watch server; it is closed off entirely for the plain, copy-anywhere generate output.
