A corpus rename left two docs/ prefix strippers behind, and both fail silently graph notebook paths i want to be able to run the notebook graph with hmr whenever something updates within its data. maybe let's explore this in a worktree

The corpus moved from docs/ to .mycelium/, and two prefix strippers kept stripping the old prefix, in generate and in fillWhere. A prefix that matches nothing strips nothing, so neither one has matched anything since the move, and every node address the page carries has been an absolute filesystem path ever since.

That stayed invisible locally, where a path under one's own home directory still opens in a browser. It stopped being invisible on the published site, where the pane's own "where" link and the permalink hash both read as /home/runner/work/mycelium — a path meaningful only on the machine that built the page.

The fix names the corpus directory instead of writing the old path as a literal, the same rename discipline this project already argues for elsewhere. A stripper naming what it strips cannot go stale the way one spelling it out can.
