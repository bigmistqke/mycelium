The lib-template spec deferred a directory convention for *.lib.html files until a second real example existed, since graph.lib.html alone could not say whether "beside its own template" was the rule or just where the first one happened to land.

webdriver.ts is that second example, and it settles the question by contrast rather than by generalizing: it reads no file relative to its own location at all, unlike graph.lib.html, which reads graph.template.css and tokens.css through a path computed from where it sits. So the convention is not one fixed directory for every lib file — it is that a lib file sits beside whatever assets its own functions read, and .mycelium/lib/ is where one lands when it reads none. webdriver.lib.html goes there; graph.lib.html stays put.
