Branch language lint by file extension: real HTML DOM for .html, markdown-aware paragraphs for .md we maybe need different paths determined by the file-extension

language lint only ever read text piped in on standard input, with no document behind it. That was correct for something like a commit message, which is not a file, and wrong for a real file such as README.md — a document, just not HTML, so the two rules needing real markup could never fire for it either way.

lint now also accepts a file path. An HTML file parses into a real document and strips the same protected elements the corpus audit strips. Any other extension gets treated as markdown and converted to just enough HTML for the markup rules to have something real to read — not a renderer, since links and tables and nested lists stay literal text, only enough structure for a rule built against HTML to see what it needs.
