figure.template.html declares elements but nothing ever conforms to it, unlike every other template family for figure.template.html -> i wonder if we should make an additional category 'element.html' that is a template that provides a custom-element but no documents

Building explore generate index's Templates/Commands split surfaced this: the split reads declaresATemplate — whether a host file has a <template id> — to decide whether a family belongs under Templates (instances can conform to it) or Commands (nothing ever will, by design, and the page no longer prints "no files yet" for those).

figure.template.html fits neither reading cleanly. It declares three element templates (figure-graph, figure-node, figure-edge) and ships a real figure.element.js, so declaresATemplate puts it under Templates. But nothing has ever conformed to it as a standalone document, and nothing is expected to: its elements get embedded inside other documents instead — chain.canon.html, for one — the way an earlier spike already found. So it sits under Templates showing "no files yet" forever, same as a command file does, for the opposite reason: a command declares no schema at all, while figure declares one that nothing outside it ever uses directly.

Every other *.element.js in the corpus — notebook, test, experiment, graph, chain — is a support script for a family that already has real conforming documents. Figure is the only file shaped this way right now, which is why a third category for it got proposed and then set aside: one member is not yet a pattern worth naming.
