A walk that skips dot-entries makes a dot-named corpus invisible to itself corpus audit

walkFiles steps over any entry whose name starts with a dot, which keeps .git and .claude out of every audit. Rooting the corpus at .mycelium/ puts the corpus itself behind that same filter. A walk handed the directory by name still works, because nothing filters the root a caller names; a walk starting one level above finds nothing at all.

An audit reads through AuditFs, which roots one level above the corpus so a rule can reach src/. Twelve call sites across five documents therefore name the corpus with the literal string "docs". Each one returns an empty list rather than an error once the directory has another name, and an audit finding nothing to check reports success.

The failure has no symptom, which is what makes it worth writing down. Every audit passes, the count of checked documents drops, and nobody reads a count that has always gone up. Watching that count hold at 1001 across the rename is what said the audits still had the corpus in view.

AuditFs already carries root, and the corpus directory belongs beside it as the same kind of fact. Handing an audit that name removes the literal rather than updating it, so the next rename touches one line.
