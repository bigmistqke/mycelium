conforms-to moves from a head link to an attribute on the element making the claim

Imported from the project’s earlier decision log, frozen 2026-07-23.

<link rel="conforms-to"> in <head> can only assert one type for a whole document, which breaks composition: a decision nested inside a spec's design section cannot declare its own conformance next to itself.

Replaced with data-conforms-to directly on the element making the claim. A document can now carry one typed root plus any number of typed elements nested inside it, each independently findable via querySelectorAll('[data-conforms-to]').

The data- prefix wins out for consistency with the existing data-rel edge convention, and because — unlike <link rel> — there is no real HTML attribute being reused once conformance moves onto custom elements.
