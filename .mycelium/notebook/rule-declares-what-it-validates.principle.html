A rule declares what it validates on its own element, not by which directory holds it

Three shapes were on the table. A comments.template.html family with its own rules. Scope encoded as a directory, rules/js/jsdoc/. Or an attribute on the rule element.

The family lost to no family calls another family's lint. A comments family could not reuse language lint, so it would need a second rule loader, checker and autofix, and the two would drift.

The directory lost because a directory here is convenience. pathFor already derives the folder from the filename's suffix, so the document is the source of truth everywhere else. Nesting would also have forced a scope path into every show, update and link argument.

So data-validates sits on the root element, beside data-conforms-to, and reads: all, html, markdown, javascript, javascript/comment, javascript/jsdoc. A prefix match means javascript covers both narrower kinds.

Required rather than optional, which is the part worth arguing with. An absent attribute would mean everywhere, and two rules here cannot run everywhere: they need markup, so they never reach a comment whatever they claim. Requiring the attribute turned that accident into a statement on all six.
