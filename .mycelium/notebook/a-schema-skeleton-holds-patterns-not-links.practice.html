A template's href is a pattern, so a link rewriter that reads text corrupts the schema schema distribution

A <template> skeleton carries one placeholder per field, and an attribute on a placeholder is a regular expression the validator tests an instance against. So href=".+" inside a template says an instance must carry some href rather than pointing anywhere.

Rewriting seeded links with a pattern over the text hit those too. Every href=".+" came back as a URL ending in .+, and eleven documents then failed against a rule that had stopped describing a link at all. The failure named the instances rather than the template that broke them, which is the wrong end to start reading from.

A parse tells the two apart, because the tree says which subtree is a template and which is markup. parse5 hands back each attribute's byte range, so the edits splice into the original and every other byte survives as somebody wrote it. Reserialising a whole document would have been the other way to do it, and it rewrites whitespace nothing asked it to touch.
