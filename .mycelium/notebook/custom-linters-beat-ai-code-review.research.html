A team ditches AI code review for custom linters, and the reasons line up with why validate exists here deterministic-checks

Swizec's team paid roughly $1000 a week for an AI review bot and got comments back ten to thirty minutes after every push, generic and detached from the team's own values. They replaced most of it with custom linters — rules like no raw color or descriptive test names — that run in seconds, work inside the editor, and gate a commit before it ever reaches a pull request.

The shape of the argument is the same one this project's own linting design already rests on: whatever a rule can check deterministically should run as a rule, fast and pre-commit, and a model's judgment is worth spending only on what a rule cannot state — architecture, whether an abstraction is premature, whether a test actually exercises the failure it claims to. Reading this after the fact is convergent validation rather than the origin of that split.
