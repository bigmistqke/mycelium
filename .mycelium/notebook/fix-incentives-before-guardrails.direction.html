Fix the read path in this pass; defer the plan-step record guardrail

Two calls resolved together, because they trade against each other. The question was where to spend this pass: on making capture read (so it pays the writer back) or on making capture enforced (so it happens regardless).

Read path: in scope now. /recover was the only mechanism that ever read the graph back, and it drives the frozen deciduous CLI. This plan already deleted it — with nothing replacing it.

That leaves the graph write-only, which is precisely the failure mode the prior art describes: the writer is not the beneficiary, so capture decays to tax. Deleting the read path in the same pass that adds write pressure gets the incentive exactly backwards. So the deletion and the replacement become one unit of work, not a deletion now and a replacement someday.

Layer 4 (plan-step record guardrail): deferred. The idea is a per-task plan step whose plan-check asserts a knowledge node links back to task-N — the plan cannot go green without its own record, using the derived-status machinery already built rather than an agent remembering.

It is a good guardrail and it dogfoods well. It is deferred anyway because the check has to query the graph by shape, and the graph's shape is still moving: the tag axis is undecided and the ~183 cut has not happened. Writing the query now means writing it twice.

Accepted cost of the deferral. This plan runs without the guardrail that would have made it record itself — the exact gap layer 4 exists to close. That is a deliberate bet that layers 1 and 2 (make the graph get read, make capture cheap at the moment) move compliance enough on their own that the guardrail is tuning rather than rescue. It is also testable rather than assumed, which is the standing lesson from the 52% figure: measure the rate after this pass instead of promoting a prediction to a law.

Note on hooks, since this plan deletes two of them. Adding a SessionStart read hook is not a reversal.

The removed hooks fire on a rate (every 15 minutes of editing, every commit) and write nodes. This one fires at a moment that actually exists (a session begins, context is empty) and only reads. That distinction is the whole content of gate on shape, not rate.
