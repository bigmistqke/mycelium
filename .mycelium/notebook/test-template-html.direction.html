A test template: a test is an HTML document you open, and its statuses flip from PENDING there are 2 kind of tests that probably will appear in this codebase: node-tests and browser-tests. .html is already the language we speak. it's maybe about creating a test.template where we simply have to open the file and wait for all the <test-status> to go from PENDING to SUCCESS|FAILURE

Raised against the open question about the figure layout engine, and it answers it by changing the venue rather than the subject. The engine's decisions read measured boxes, happy-dom measures nothing, so the two candidates on the table were a pure-function extraction driven by synthetic boxes, or a headless browser as a test framework. This is a third: the test is a document, and a browser only opens it.

The branch expects two kinds. A node-test reaches the filesystem and the CLI's own source. A browser-test reaches a rendered page. Both are the same kind of document.

Every other document family here is HTML conforming to a template, so a test being HTML costs no new notation. What is new is that the document reports on itself: each test-status reads PENDING in the file, and the runner rewrites it to SUCCESS or FAILURE in the page.
