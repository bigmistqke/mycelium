Plan stopped being authored on 2026-08-07 and every one of its 286 recorded steps already read completed, so deleting it dropped nothing anyone still needed. The question was whether spec should grow plan's other half — a runnable check per step, the way plan-check ran a real command and derived a task's status from its steps rather than storing it by hand.

Every spec written since plan lapsed went straight from design to same-session implementation, with nothing needing a checklist that outlives one sitting. And where a checkable claim genuinely matters, this project already has a home for it: canon's behaviour, which names a real script and carries a verdict. Building a second checkable-step mechanism into spec would duplicate that chain rather than fill a gap.

The gap is real anyway, and worth naming rather than assuming closed. If a future effort needs multi-session task tracking again — the kind plan-doc and plan-task gave six-task efforts like the harness-shape plan — spec has nowhere to put it today. That is the condition to watch for, not a reason to build the mechanism now against a workflow the project has already outgrown.
