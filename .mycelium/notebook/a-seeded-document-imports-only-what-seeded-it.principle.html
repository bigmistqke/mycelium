A seeded corpus sits in somebody else's repository with one package installed. Its documents run through the module hook, which mints each module beside the real file, so a bare specifier resolves from the consumer's own tree. Anything that package depends on is reachable there only when the package manager happens to flatten node_modules.

One rule reached for retext directly and failed under pnpm while passing under npm, which is the worst version of this: it works until somebody switches tool. Re-exporting the library through mycelium/retext costs one line and removes the question.

The rule sorts the rest of the seed as well. A .ts helper beside a template pulls in typescript or marked, so copying one into a consumer would carry the same problem; nothing in the corpus links to those files either, so the package keeps the only copy and the templates import them by name.
