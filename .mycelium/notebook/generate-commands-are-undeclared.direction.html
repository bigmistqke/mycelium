Generate commands are plain imperative functions, undeclared the way every document in the corpus is lib-code runtime i also not love how undeclared these generate scripts are. it's not such a clean fit

A document in this corpus declares what it is: data-conforms-to names a schema, and validate checks the document against it. A generate command declares nothing. It is discovered by naming convention — export function generate({ fs, args }) — and documented only in a JSDoc comment that --help happens to print back; nothing about what it actually does is machine-checkable.

That absence is exactly why the three generate commands compose so differently from each other. notebook generate graph and canon generate chain/measure both call graphPage() and get graph-serve.ts's --watch for free; explore generate index reimplements its own shell from scratch, including the generic parts that have nothing to do with graphs, and has no watch mode at all; canon generate sits in between, sharing the shell but still missing --watch (see the existing followup asking for the same server notebook already has). Whether a command's output conforms to the graph-page shell, and so what it gets for free, is a fact only readable by opening the function — nothing states it the way a document states what it conforms to.

The corpus's own description of itself is "a document is the source of truth, and the tooling reads it." Every generated artifact in the corpus comes out of a command, and commands are the one part of the system that description does not yet cover.
