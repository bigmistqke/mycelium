Duplicate loadModule/loadCheck rather than share it, once runtime.js's whole reason for existing was one five-line function

loadModule/loadCheck was a five-line data: URL import wrapper shared across two contexts — three Node modules and one browser page — through a whole shared file, a globalThis attachment, a script tag, and its own type declarations. That is more machinery than what the function itself carries.

The fix moved the Node side into utils.ts as a real, typed export, and duplicated the same five lines directly inline at the one browser call site instead of routing the browser through the shared file too. Sharing five lines across a boundary that only one side can import cleanly costs more than writing the five lines twice.

 answers a narrower question than that decision did -- not how to share across Node/browser without CORS, but whether a five-line function with two call sites needs sharing machinery at all
