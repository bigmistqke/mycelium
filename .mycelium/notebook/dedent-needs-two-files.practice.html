Printing a stored script needs a computed dedent, and one test file would have hidden that

The first version stripped four spaces from every line of a check. It looked right on the outside-references rule, whose script opens on its own line under four spaces of indentation.

It mangled the paragraph-length rule, whose script opens on the same line as the tag and therefore starts flush left. Stripping four spaces there ate one level of the check's own nesting, so a for body printed further left than the for.

The fix computes the shared leading whitespace across the block and strips exactly that. Six rules exist, and they split two ways on this, so running the command against a second file is what caught it.

The wider point is about what a display bug looks like. Nothing failed and nothing threw. The output stayed plausible, and only reading the code it printed against the file it came from showed the difference.
