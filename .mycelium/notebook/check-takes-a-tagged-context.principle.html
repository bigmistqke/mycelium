A check receives a tagged context, because a rule scoped to everything cannot know what it is holding

The second argument to a check meant a DOM element for document prose and nothing for a comment. Reading it as whatever this prose is attached to would have let a rule about code receive a declaration in the same slot, at no migration cost.

That fails on the rules scoped to everything, which is four of the six. Such a rule would receive an element from one source and a declaration from another with no way to tell them apart, and the scope it declares says all, so the declaration cannot disambiguate it either.

So the value carries its own tag: { kind, node, language }, where kind is the same vocabulary a rule declares. A rule reads the tag rather than guessing from where it was called.

Three of six rules changed, and each by one line. The three that read only text ignore the argument entirely, which is the property worth keeping — a rule about sentence length should never learn what a declaration is.
