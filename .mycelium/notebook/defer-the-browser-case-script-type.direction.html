Leave the browser case's script type alone for now, and settle the asymmetry in a follow-up

Two spellings for one idea is a concept the project pays for on every reading. mycelium/test and text/mycelium-test name the same kind of thing and share no shape, and the difference between them carries a rule about which runtime and which language rather than anything about testing.

Three candidates got weighed. Naming the runtime in every mycelium type fails on the counts: six of the seven types are tooling that will only ever run under Node, so marking one exception would put node on six names. Renaming only the browser case to mycelium/browser-test is strictly worse than today, keeping the invented name and breaking the prefix contract besides.

The candidate worth building is type="module" with a default export, which invents no name and makes both kinds of case one shape. It costs the browser running the module at load, so a case must export and do nothing else, and a parse error arrives as a page error rather than as that case failing.

Not now, because the fold already moves eighty cases and this would move the same eighty a second way. The fold rewrites every case's tag, so the follow-up lands cheaply straight after it.
