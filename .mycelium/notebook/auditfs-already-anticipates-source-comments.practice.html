AuditFs is already rooted above docs/ specifically so a language rule could reach a source-file comment

src/api.ts's own doc comment on AuditFs says why it is rooted one level above docs/ rather than at it: "a rule about language applies to a comment in a source file as much as to prose in a document, and an audit that can only see HTML can never say so." Nothing uses that reach yet — prose-follows-the-language only calls fs.list('docs', { ext: '.html' }) — but the interface already supports listing and reading files by extension outside docs/, which is most of what checking JSDoc and comments in .ts/.js files would need on the audit side.

Not implemented now: the immediate request was extension-based dispatch in lint for .html versus .md. Comments/JSDoc would need its own text-extraction step (strip code, keep only comment bodies) the same way prose() strips markup down to checkable text for HTML today.
