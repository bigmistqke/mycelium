A container of repeated links reads to the prose lint as one sentence, so the word limit divides by the number of links language canon

Twenty-two grounding references landed across thirteen axioms, and prose-follows-the-language failed four of them for sentence length. Each label was around twenty words. The reported sentences ran to 48, 53, 54 and 59.

extractProse appends a newline after a tag in BLOCK_TAGS, and neither canon-references nor a is one. So three labels inside one container concatenate with no separator, and the rule counts them as a single sentence. An axiom with one reference passes at twenty words; the same axiom with three fails at the same twenty each.

This is not new and it is not about references. Any claim carrying two data-rel edges already merges their labels the same way. It has stayed invisible because every edge label in the corpus is a short phrase — the principle this refines, the files it answers for — and three of those still fit.

The check was right about the labels, which had grown into sentences. It was right for a reason that will mislead somebody later, though: the fix it points at is shortening, when the fault is that a repeated inline field has no boundary. Two medium labels fail where one long one passes.
