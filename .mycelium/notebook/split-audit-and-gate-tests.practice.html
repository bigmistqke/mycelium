Test an audit by calling it, and the gate by running it

The sandbox exists to test a command end to end, and the spawn buys the argument parsing, the path picking, the serialization and the exit code — each of which is a scar in this repository. Pointing it at an audit went badly: a sandbox corpus holds no specs, no knowledge nodes and no language rules, so several audits pass vacuously there while every-link-resolves fails on the templates' own outbound links. The exit code carries no signal, and a case has to scrape output.

An audit is a different subject. It is a function of a corpus, and AuditFs is the whole of what it needs, so a case builds one over documents in memory and reads the returned list. The check still comes out of the document declaring it, through the same module hook, so the real audit runs rather than a copy.

So the split follows the subject: logic gets called, the gate gets run. Six chain cases went from a process each to two seconds for all of them, and the two behaviours that genuinely need a process kept it.
