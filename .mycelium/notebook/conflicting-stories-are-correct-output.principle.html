Conflicting stories are the right output, and the code decides between them

A codebase holds several stories at once, and some of them conflict. A derivation that resolves this early is lying.

First separate plural from contradictory. How data flows and how to extend this do not conflict. They are two projections. Keep both.

Real contradiction is two claims that cannot both hold. Do not ask a person to settle it in the abstract. Derive checks from both and run them against the code. The code is the arbiter.

Whichever claim the code breaks is either dead or aspirational, and that difference matters. The architecture a team enforces in review and the architecture that shipped are both real, and usually not the same.

Two cases fall out, and they are the useful ones. If a claim holds in one region and fails in another, it is not false. You have found its boundary, usually a boundary in time, matching the eras the code layers into.

So a failing check can narrow a claim instead of killing it. And if both claims fail in the same place, that region has no story at all. Nobody's model covers it, which makes it the most valuable thing the whole apparatus could point at.
