Template: spec

Node type: spec
Purpose: the shape a design/brainstorming document takes when written as a v4 node instead of Markdown
Sibling of: ./decision-nodes.html, the six deciduous node-type templates

Why this template exists

The superpowers:brainstorming skill's default is to write an approved design to docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md, with an explicit carve-out: "user preferences for spec location override this default." v4's preference is that a spec is a node like any other — HTML, not Markdown, and conforming to a template like any other instance in this graph. This template is that override, made concrete.

Per DESIGN.html's "no imposed shape" principle, a spec document's body stays free-form prose — sections, tables, diagrams, code, whatever a given design needs. Only a minimal header is checked: enough to identify the document and its state, not to constrain its content.

Shape

<spec>
  <title>…</title>
  <status>draft | approved | implemented</status>
  <date>YYYY-MM-DD</date>
</spec>

status tracks the brainstorming skill's own lifecycle: draft while under discussion, approved once the user signs off on the design, implemented once the plan it led to has shipped. Everything after the <spec> block is ordinary document content, related nodes reached the usual way: <a data-rel="…">.
