Build a per-node review surface for the 400 frozen deciduous nodes 80 active

The import cut was settled by user call as read every node and decide individually, rather than applying a criterion mechanically and accepting the resulting number. 400 nodes is too many to adjudicate in conversation, so this builds a scannable review surface: every node with a recommended keep/drop, a one-line reason, and a per-row override.

Reading all 400 produced a finding that changes the criterion. "Keep what git cannot tell you" is necessary but not sufficient. It keeps #43/#44 ("Package manager choice" → "Use pnpm") — a rejection git genuinely does not record and that nobody will ever want. It also keeps #2–#5 (TypeScript vs Rust vs Hybrid) and #116–#123 (Louvain vs Infomap vs Leiden, with real complexity and connectivity analysis), which are foundational. Identical shape by the criterion, opposite value. A second filter is needed — did the choice have consequences? — and it is a judgment the criterion cannot make, which is precisely why per-node review is the right call here.

Second finding: the spec's least-certain block is backwards. The spec names the 87 January vision observations as the least certain material. Reading them, they are among the most valuable in the corpus: two prior-art surveys (#228–#244 covering Intentional Programming, MPS, Unison, Alloy, TLA+, Hazel, Subtext; #278–#288 covering MLIR, Nanopass, refinement types and the EE verification parallel), plus #245/#246 on why Intentional Programming never shipped — which is the same question this project is currently living inside. The genuinely low-value block is the Jan 12–14 implementation record, not the vision material.

Defaults encoded in the surface. Bare implementation records (Committed:, Implemented, Added) and feature-request goals default to drop, since git holds them verbatim. Decisions and options default to keep but are flagged soft, because that is exactly where the consequence filter has to be applied by hand. The seven nodes the v4 graph already cites are locked keeps — the graph cannot be left unable to resolve its own citations.
