Build a per-node review surface for the 400 frozen deciduous nodes 80 active

The import cut was settled by user call as read every node and decide individually, rather than applying a criterion mechanically and accepting the resulting number. 400 nodes is too many to adjudicate in conversation, so this builds a scannable review surface: every node with a recommended keep/drop, a one-line reason, and a per-row override.

Reading all 400 produced a finding that changes the criterion. "Keep what git cannot tell you" is necessary but not sufficient. It keeps the package-manager decision and its single option, "use pnpm" — a rejection git genuinely does not record and that nobody will ever want. It equally keeps the implementation-language decision weighing TypeScript against Rust and a hybrid, and the community-detection comparison of Louvain, Infomap and Leiden with real complexity and connectivity analysis, which are foundational. Identical shape by the criterion, opposite value. A second filter is needed — did the choice have consequences? — and it is a judgment the criterion cannot make, which is precisely why per-node review is the right call here.

Second finding: the spec's least-certain block is backwards. The spec names the 87 January vision observations as the least certain material. Reading them, they are among the most valuable in the corpus: two prior-art surveys covering Intentional Programming, JetBrains MPS, Unison, Alloy, TLA+, Hazel and Subtext, then MLIR, Nanopass, refinement types and the EE verification parallel — plus the analysis of why Intentional Programming never shipped, which is the same question this project is currently living inside. The genuinely low-value block is the January implementation record, not the vision material.

Defaults encoded in the surface. Bare implementation records and feature-request goals default to drop, since git holds them verbatim. Decisions and options default to keep but are flagged soft, because that is exactly where the consequence filter has to be applied by hand. The nodes the v4 graph already cites are locked keeps — the graph cannot be left unable to resolve its own citations.

Superseded 2026-07-30. The keep/drop axis this surface was built around was replaced by link, do not tag: a node is imported only if something can link to it, which makes relevance a property of the topology rather than a per-node judgment. The surface remains useful as a reading view of the whole corpus.
