A node should carry a claim, not an incident 80

Three attempts at this rule in one day; the first two did not survive.

Attempt 1 — "what belongs in commit history should not be repeated here." Too strong, and wrong in four ways. Git is not read: a session start surfaces the graph, nothing surfaces git log. Commits cannot hold edges, so anything whose value is its relation to another claim has to be a node regardless. Commits are immutable, so correcting a claim a commit made requires restating it somewhere else deliberately. And it is unapplicable at write time, since the node is usually written before the commit exists.

Attempt 2 — "each fact has one owning container." Better, but it made the question where does this go when the real question is should this exist.

What survived: the test is altitude, not container.

  • A claim could have come out differently, and someone could disagree with it. Derive, don't declare is a claim.
  • An incident is a record of something that happened. "The task status field went stale after task 1" is an incident.

The incident is evidence for the claim; it is not itself worth a node. Log the claim, and let the commit message hold the incident that prompted it.

Why this is the shape of the volume problem. The 47% action-node figure was read as a discipline failure. It is at least as consistent with diligence aimed one level too low — people recording what happened, faithfully, when what was worth recording was what they now believe. That reframing is testable and has not been tested.

Limit worth stating. Neither shape audit catches this. A node restating an incident has a detail and a short title, so title-length and hollow-action both pass it. The audits narrow the failure modes; they do not close them, and this one stays a judgment call.
