Commit, plan step, and node each own a different fact; duplication is the failure 80

Prompted by a direct challenge: task-2 got no action node on the grounds that it had nothing non-obvious to say, while task-1 got one. Checking the two artifacts side by side, all four paragraphs of task-1's node also appear in commit d485978. The node is fully redundant with git, so the distinction was wrong and task-1 should not have had one either.

Why it exists: it was written to pre-empt the 15-minute hook, minutes before that same task deleted the hook. A node produced to satisfy a gate rather than to record something is exactly the artifact the harness was measured producing.

The rule is about ownership, not interest. The question is never "was this worth saying" — it is "which container already owns it":

  • Commit message — what this diff does and why it is shaped this way. Dies with the diff, and git already keeps it.
  • Plan step — how execution differed from what was planned.
  • Knowledge node — reasoning that outlives the diff: a rejected alternative, a reversal, evidence, a rule.

Writing the same fact into two of them is the failure mode, and it is the one that produced the 47% action-node figure — not laziness, but diligence pointed at the wrong container.

Gap this exposes in the audits. Neither planned audit catches the redundant node. It carries a detail, so hollow-action passes it; its title is short, so title-length passes it. Both check shape; this node's defect is redundancy with git, which shape cannot see. A node whose detail merely restates its own commit message is invisible to the gate — so the audits narrow the failure modes, they do not close them, and the remaining judgment is still human.
