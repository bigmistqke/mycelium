Hyphenate every invented tag and prefix by family, not by brand 88 completed

Imported from deciduous #389.

Two forcing reasons. Unhyphenated custom tags had already collided with real HTML elements twice — title, worked around with CSS, and option, one of the six planned node types. The Custom Elements API also rejects unhyphenated names outright, which would foreclose real interactive behaviour later without a breaking rename.

The prefix adds information rather than branding: spec-* for design-document types, graph-* for the six node types (later renamed knowledge-*).

  • Root type = family-type (spec-doc).
  • Fields carry only the family prefix (spec-title), since a field belongs to the family rather than to one type within it.

Consequence for files: template files are named after the family, not any single type, so one file can bundle several related template entries addressed by fragment. This reverses an in-progress plan to split the six node types into six separate files — the prefix makes them safe to collocate, so physical file separation was doing no work.
