Spec template fields are named sections, not a three-field header 85 completed

Imported from deciduous #385.

Queryability is bounded by tag membership, not by structured-fields-versus-prose. A container tag can hold arbitrary freeform content and still be addressable by tag name across every instance.

The first spec template declared a three-field header (title, status, date) and left the rest of a design document as untagged prose, so almost nothing in a spec was actually queryable.

Revised to declare named sections inside the root: problem and design required, out-of-scope and open-questions optional — and optional means omitted rather than present-but-empty. Each section still holds whatever content a given design needs.

 the first correction in the template series: sections, not a header
