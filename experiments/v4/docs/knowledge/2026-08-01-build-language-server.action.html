Build a language server that gives every script block its own virtual file 90 completed

Volar's getExtraServiceScripts is what makes this possible: it returns several TypeScript files from one source file, each with its own name, so a block gets its own module scope rather than being concatenated with its neighbours. A block's type decides its language by the same prefix test src/script-hooks.ts uses to decide its format, so the editor and the loader apply one rule in two places.

Checked by driving the real server over LSP rather than by reading the plugin. It reports diagnostics at positions in the HTML file, hovering the fs parameter answers CommandFilesystem, two blocks in one document declaring the same name produce nothing, and a type annotation is accepted in a mycelium/* block while the same annotation in the module block beside it is refused.

Its first run over the corpus found a real gap. The contract in src/api.ts had no commit, and plan check calls it deliberately to flush the steps that passed before throwing for the ones that did not.

One limit worth recording: getExtraServiceScripts is available to a language server and not to a TypeScript plugin, so this cannot be repackaged as a plugin without losing the property it exists for.
