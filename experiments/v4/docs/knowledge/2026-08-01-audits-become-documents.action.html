Make an audit a document, and wrap the five that exist 88 completed

An audit was the one thing here that was not a document: a bare script with two attributes, no title, nothing validating it, and no address anything could link to. That is why title-length stayed invisible long enough for a rule duplicating it to be written by hand.

template-audit declares a title, optional detail and a required script. The type lives in template.template.html because an audit belongs to the system rather than to any project: every project using this has audits, and only this one has a knowledge-goal. The prefix names the vocabulary a tag comes from, and this tag is only ever used inside another template.

data-audits, data-touches and data-expects stay on the script. The element adds only what had nowhere to live. A second home for the same value is the drift found repeatedly today, most recently when the title limit went from one place to six.

Verified: all five audits still discovered and running, the enforcing rule still catches an injected violation, and an audit written without a script fails validation by name. That last one is the schema doing work no audit could: an audit that holds nothing cannot be written.

What the schema still cannot say is that the script carries data-audits, since the vocabulary constrains children and their text and nothing else. Such an audit would validate and never run. That is the deferred attribute gap, and it now has a second caller, which is the condition that decision set for closing it.
