Inject a TextMate grammar so mycelium/* script blocks embed source.ts 75 completed

The extension currently ships no contributes.grammars at all — it is a pure LSP client. Fixing the source.unknown scope this observation found means adding one: a small injection grammar that recognizes type="mycelium/…" and embeds source.ts for the block body instead of falling through to source.unknown. Attribute highlighting inside the opening tag is kept by including the built-in grammar's own #attribute rule rather than reimplementing it.

The first version targeted text.html.basic and did nothing — reported back by the person testing it, still wrong after a reload. Reading VS Code's actual bundled grammars settled why: opening a .html file tokenizes with text.html.derivative (extensions/html/syntaxes/html-derivative.tmLanguage.json), the grammar registered for the html language. That file reaches text.html.basic only through { include: "text.html.basic#core-minus-invalid" }, a reference to one repository rule, which never pushes text.html.basic onto the scope stack. An injection selector naming it therefore never matches a real buffer. Retargeting at text.html.derivative, in both the grammar's own injectionSelector and the extension's injectTo, is the actual fix.

Checked outside the editor rather than by reloading and looking again: tokenized a sample block through the real vscode-textmate + vscode-oniguruma engine, loading the same grammar files VS Code ships. Against the first version every content line came back source.unknown, reproducing the report. Against the fix, import/type/export/function/const/return each carry their real TypeScript scope (keyword.control.import.ts, storage.type.function.ts, …).
