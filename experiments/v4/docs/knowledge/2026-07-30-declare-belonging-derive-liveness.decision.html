A status enum assumes linear history with a single endpoint. What deciduous #5 calls the missing retirement concept is not a property of each node: v0's decisions are dormant because the v0 exploration was abandoned — one fact denormalized across 200 nodes, and the next abandonment costs another 200 stamps.

Split what status conflates. Belonging (which exploration a node is part of) never changes and can be multi-valued, so it is declared, as a topic tag. Liveness (whether it still holds) changes because of events outside the node, so it is derived from topology: one v0-abandoned node with edges to what it supersedes, and an audit computes reachability.

Grounded in the project's own record — #325: Composition makes decision status DERIVED, not declared… don't store it, derive it from the layer below. Solves metadata maintenance by eliminating the metadata. And #364: Because it is derived it CANNOT ROT.
