Build the dictionary family: template, two types, and its authoring commands 85 completed

Template before entries, reversing the order suggested earlier in the same session. Seeding first would have meant hand-authoring instances, which is the one thing the project instructions forbid, so there was no way to seed "properly" until the family existed.

A new family costs one file. validate discovers templates and instances by walking the tree, and run.ts resolves a family by filename, so nothing had to be registered anywhere. The family appeared in mycelium run --help immediately, which is the roster built earlier today doing its job unprompted.

Open question 1 of the spec is answered, by precedent rather than by argument: a term carries a required one-sentence dictionary-meaning and an optional free-form dictionary-detail, the same split knowledge-title and knowledge-detail already make. Questions 2 through 5 are all audit questions and stay open; this pass builds no audit.

One departure from both sibling families, argued in the template's own prose: dictionary entries carry no date prefix. A date records which exploration a node belongs to, and a word does not belong to an exploration. A dated slug is rejected for that reason rather than the doubling reason the other two families reject it for.

A bug was found by testing rather than by reading: add writes only the fields its own type declares, so add term --pass "…" dropped the flag in silence and reported success. Now rejected by name, in both add and update, before anything is read or written. This is the same silent-drop shape as the stale command list that opened the session.
