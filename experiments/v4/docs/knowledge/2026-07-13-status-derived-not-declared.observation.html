Composition makes decision status derived rather than declared 88

Imported from the project’s earlier decision log, frozen 2026-07-23.

Claims bottom out in tests, so status can be computed instead of stored:

  • Tests exist and pass → the decision is live.
  • Tests gone because the constrained code is gone → the decision auto-retires.
  • New claims contradict old claims → superseded, with the exact colliding claim identified.

Same trick as a materialized view over an event log, and as deriving an AST from dataflow rather than hand-authoring it: don't store it, derive it from the layer below.

It solves metadata maintenance by eliminating the metadata.
