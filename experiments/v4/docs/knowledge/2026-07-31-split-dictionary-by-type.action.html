Split the dictionary into terms and rules directories 85 completed

Forty-nine files in one directory interleave alphabetically, so neither list can be read: attributes, attrs, audit, then a rule, then more words. Thirty-five terms and fourteen rules now sit in dictionary/terms/ and dictionary/rules/.

A split by type, not by subject. A term goes with terms and a rule with rules, so there is no judgment to make on each entry. Splitting by subject would put one on every entry, which is the cost link, do not tag refused for topic tags, and is why an earlier suggestion of per-domain directories was argued against here.

The type suffix stays on the filename even though the directory now repeats it, and it stops being redundant: every command taking an existing entry derives the directory from the suffix, so a caller still writes harness.term.html and never a path. A name without a recognised suffix is rejected by name.

Cheap because of what the entries already link to. Every cross-reference in the dictionary is term to term, so those relative hrefs survived the move untouched; exactly one link pointed in from outside. What did break was depth: forty-nine files carried ../templates/ in their conformance declaration and stylesheet links, and each needed one more level. The seed markup in add needed the same repair, which the corpus could not have caught, since a file that does not exist yet validates clean.
