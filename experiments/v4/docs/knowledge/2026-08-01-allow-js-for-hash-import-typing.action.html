Turn on allowJs so a #id import gets real inferred types, not just resolution 85 completed

A direct follow-on to resolving #id imports: that action fixed module resolution, but a mycelium/* block importing a type="module" sibling by id still hit ts(7016), "implicitly has an 'any' type" — TypeScript found the file but, with allowJs unset, refused to open it for type information at all.

Set allowJs: true in tsconfig.json, leaving checkJs off. allowJs lets a .js file into the program so its inferred types reach an importer; checkJs would additionally lint the .js file's own contents under this config's strict settings, which a type="module" block should not be, since it runs in a browser and was never written against this project's TypeScript rules.

Checked against a fixture with a plain JS function (function YOLO(n) { return n * 2 }) exported from a type="module" sibling and consumed by id: the "cannot open" error is gone, TypeScript infers YOLO's shape from the function body itself, and a real mismatched-type assignment on the call site is correctly caught. The full corpus (node editor/check.ts, no arguments) came back byte-for-byte identical to the pre-#id-resolution baseline — 182 diagnostics across 9 documents — confirming allowJs does not pull in or newly lint anything the project did not already have in scope.
