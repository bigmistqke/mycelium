Rules load through the engine, so a rule may import a library 88 completed

A rule used to load from a data URL built out of its own source. That works for a rule that is one self-contained pattern. It fails for any rule that needs help, because a data URL carries no base to resolve a package name against. Node rejects the request outright.

I asserted this limit before testing it, and the user asked whether I was sure. I was right about the limit and wrong about the cost. A probe showed that a script inside a document resolves a package by name through the engine's own loader, and that the same script can import the runtime by relative path. The change is a few lines in two places, not the refactor I described.

Rules now load the way every other script here loads. The passive-voice rule proved it by importing a library on its first run.

One thing goes. A rule loaded this way runs under the runtime only. The other scripts in these templates also run in a browser through the same data URL trick, and a rule no longer can. No page demonstrates a rule today, so nothing breaks yet, and the browser path closes.
