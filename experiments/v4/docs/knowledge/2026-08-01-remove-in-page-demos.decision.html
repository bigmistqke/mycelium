Remove the in-page demos, trading a template that proves itself for one language across every Node-only script 85 active

Six blocks, 202 lines, each ending in a getElementById call against an output element. They go.

They cost no checking. src/validate.ts compares every audit's violations against its own data-expects and exits non-zero on a mismatch, which is the same comparison the demo in knowledge.template.html performs at line 572. The demo re-runs a gate that already gates.

They cost duplication while they stay. The audits at knowledge.template.html lines 327 and 382 each carry their own copy of graph extraction, and the source says why: written out rather than imported from a helper, because the same script also runs in the demo through a data: URL, which has no base to resolve a relative import against. With the demo gone both import #extract-graph, which already exists at line 605. The same reason is what keeps a rule on a data: URL, so both mechanisms collapse into one.

What is given up is documentation, and only documentation. A demo is the browser side of a template: it shows a reader what a validator does while they are looking at it. That is worth something and nothing here replaces it. It is not the same as the property an earlier decision gave up real ES modules to protect, which was that every document opens with a plain double-click and needs no server. Every document still does. A demo removed makes a document show less, not fail to open, so that decision's claim is untouched and this one does not contradict it.

The two sides are separable, which is the reason this is a small decision rather than a large one. A demo is browser-facing documentation. A command, an audit and a rule are machinery that only ever runs under Node. Deciding the language for the second does not require the first to exist.
