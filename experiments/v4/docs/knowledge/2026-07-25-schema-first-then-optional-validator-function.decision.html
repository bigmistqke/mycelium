Generic schema check runs first; hand-written validator functions become optional 70 completed

The generic schema check runs first — required/pattern/enum/allowed-fields read off the template. A hand-written validator-function becomes optional, additive validation only, for logic the schema vocabulary can't express.

Reviewing all seven current check() functions (six knowledge-* types + spec-doc): every rule in every one of them — required fields, confidence's 0-100 range, status's enum, the "optional field present but empty" rule, the unexpected-extra-tag check — is already expressible via required/pattern/enum plus the field list itself. So in practice this resolves to full replace: all seven hand-written functions are deleted once their templates carry the equivalent attributes.

Nothing is lost by construction, not by policy — a future type that genuinely needs logic beyond the schema vocabulary can still add a data-validates script, which the crawler would then run in addition to (not instead of) the generic check.
