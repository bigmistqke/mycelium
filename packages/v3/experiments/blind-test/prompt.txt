This module is the event store of a decision-tracking tool: decisions are stored as
git commits in orphan branches (the event log), and a SQLite database is a materialized
view rebuilt by replaying that log.

Your job is NOT to write tests. Your job is to say what this module PROMISES, and then
to find what it does not say.

STEP 1 — Decompose the module's contract into PROPOSITIONS.

A proposition is a single checkable claim with this shape:

  text:         the claim, one sentence
  guard:        the condition on inputs/state under which the claim applies.
                Write this as a PREDICATE, not prose. e.g. "event.type === 'status' &&
                !NODE_TYPES_WITH_STATUS.includes(node.type)"
  answer:       what must then be true
  verified_by:  one of
                  "type"   - the type system already enforces this; no test needed
                  "test"   - it needs a test to hold it
                  "review" - only a human can judge it
                  "none"   - it cannot be checked at all (rationale, a bet, history)

RULES:
- A proposition must be FALSIFIABLE. For each one, name a concrete change to the code
  that would break THIS proposition and not its siblings. If you cannot name one, the
  proposition is worthless — drop it.
- Do NOT restate the happy path. "replay() rebuilds the database" is worthless.
  Prefer claims that could plausibly be WRONG.
- Pay attention to partial operations: functions that are only meaningful for part of
  their own input domain.

STEP 2 — Treating the guards as predicates over the module's input and state space,
report:

  GAPS
    An input or state that NO proposition speaks to. Behaviour that is simply
    unspecified. Give a CONCRETE WITNESS: specific inputs, or a specific sequence of
    calls, that reaches this state.

  CONTRADICTIONS
    An input or state where TWO propositions would give DIFFERENT answers, or where two
    operations that mean the same thing behave differently on identical state. Give a
    concrete witness.

Be adversarial. The value here is entirely in what you find that the author did not
think of. A list of plausible propositions with no gaps is a failure.
