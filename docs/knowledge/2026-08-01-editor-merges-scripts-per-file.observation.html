An editor merges every script in one HTML file, so two modules that each declare the same name collide 90

The false errors in docs/ come from one behaviour: an HTML language service builds one virtual JavaScript document per HTML file and concatenates every script it recognizes into it. Separate <script type="module"> blocks, which are separate modules with separate scopes at run time, land in one shared scope.

knowledge.template.html shows it exactly: line 279 declares const lines inside the module that starts at 249, and line 572 declares const lines inside the module that starts at 552. Two modules, two scopes, nothing wrong when they run — but the editor reports Cannot redeclare block-scoped variable on both.

The merge is not simply a mistake, which is worth stating because it explains why the behaviour is there at all. For a classic script — no type attribute — one shared scope is correct: a top-level const, let or class in a classic script goes into the global lexical scope, shared by every other classic script in the document, so two of them declaring the same name really is a SyntaxError. (var is exempt; redeclaring it is allowed.) The service applies that one correct rule to modules, where it does not hold.

Both kinds appear in this tree, so the distinction decides which errors are real. Every classic script here was checked: no two of them in the same document declare the same name, so every redeclaration error currently reported is false.

The same merge treats the concatenation as a plain script rather than a module whenever the merged text has no top-level import or export, so a legitimate top-level await is reported as an error too.

Neither error describes anything wrong with the file. Both disappear under a language server that gives each script block its own virtual file, which is what makes that the fix rather than renaming the variables.
