A comment on a declaration that is not a doc comment: 108 of them, and I wrote a fifth today 90

A doc comment declares what it belongs to. A run of line comments binds to whatever follows it, which the citation design already names as accidental: the compiler hands a leading comment to the next declaration whether or not the author meant it.

Three corrections in one session, and the third came with the count. Reading every source file the corpus names finds 108 comments that document a declaration and are not doc comments. Twenty-seven of those arrived today, in files written hours after the rule got stated.

Two kinds hide in that number and only one is a rewrite. A comment describing a declaration becomes a doc comment. A comment inside a body describes a step, and the honest fix is a name — decomposing the pane's filler into four functions turned three of those into documentation of something.

One kind resists both. A file header sits above the first declaration and binds to it, so the reader reports a comment about a file as a comment about whatever happens to come first. Nothing distinguishes the two, which is a limit any check here would inherit.
