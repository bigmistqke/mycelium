Inject validate's loaders rather than virtualise the module hook 85 completed

Running a whole validation over materials a case provides needed the command to stop reaching for node:fs. The corpus was the easy half. The scripts were not: loadCheck hands the module hook a path, and the hook re-reads that file from disk, so a document a case wrote has no script the hook can load.

One option was teaching script-hooks.ts to consult an overlay before reading. It cannot work as registered: register() runs hooks on their own thread, so a map set from the main thread never reaches them. Switching to registerHooks would fix that and change how every script in the project loads.

The loader gets injected instead. A run takes its two loaders alongside its corpus, the engine supplies the real ones, and a case supplies its own where it needs an audit that reports something chosen. This is smaller, holds no global state, and says the thing that matters: substituting code is a different act from substituting documents, and a case has to ask for it rather than get it by accident.
