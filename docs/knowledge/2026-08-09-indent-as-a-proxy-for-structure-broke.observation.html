A pattern standing in for a parser wrote a mismatched tag into eighty documents 95

The migration moving 80 checks into their behaviours had to rename three fields and leave every other mention alone, including the ones inside script text. The first attempt used indentation as the test: a tag opening a line at exactly four spaces is a field, and anything else is a string.

It anchored to the start of a line, so it renamed an opening tag and never the closing one beside it. Every one-line field came out as <canon-verdict>PENDING</test-status>, across six canon documents, before anything ran.

The assumption underneath was not the anchor. Indentation is a fact about how somebody typed a file, and is this element a direct child is a fact about the tree. Answering the second from the first holds until somebody formats a file differently, and it fails silently when it fails.

The repository already carried the answer. parseHTMLWithLocations parses with parse5 and hands back a source range per node, split into start-tag and end-tag ranges. The rewrite asks the tree which elements are children and asks the ranges where to cut, so a script mentioning the same words survives by construction rather than by luck.
