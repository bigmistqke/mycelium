Audit discovery keys on data-audits, not on the mycelium/audit type every audit also carries 95

Every audit script in the corpus carries two markers: type="mycelium/audit" and data-audits="<name>". Only the second one decides anything. Both src/run.ts and src/validate.ts query script[data-audits], so an audit dropping its type attribute would still run, and one dropping data-audits would vanish from the roster and from pnpm validate.

The type attribute still earns its place, though not for discovery: src/script-hooks.ts keys on the mycelium/ prefix to load the block as TypeScript rather than plain JavaScript.

Moving discovery onto the script type looks tidier and costs something concrete. data-audits carries the audit's name, which the roster prints and which a failure reports. A bare type carries no value, so the name would need another attribute and the marker count lands back where it started.

Two more attributes already hang off the same script, data-touches and data-expects, so an audit declares itself in attributes rather than in its type. Any change here should move all four together or leave them alone.
