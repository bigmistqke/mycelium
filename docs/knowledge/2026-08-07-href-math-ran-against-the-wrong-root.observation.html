The engine computed a link's href against a directory no instance sits in 85

A command taking two file arguments got args.href precomputed by the engine, which resolved both against docs/ itself. No instance lives there. The result came out right only when the two files shared a directory, because then the same error appeared on both sides and cancelled.

Knowledge nodes all sit in one directory, so this held for the family that introduced it and looked like working path math. Language entries sit in three, and a term linking to a rule wrote ./passive-voice.rule.html from inside terms/. Nothing had made such a link yet, so nothing had failed.

The first attempt at the canon family worked around it instead: that family's link computed its own href locally and ignored the one the engine handed it. Two mechanisms for one job, and the engine still handed every canon command a wrong value that any later reader would trust.

A family knows where its own instances live and the engine does not, so the fix is a pathFor the family exports and the engine runs its math through. Each family now declares one, including knowledge, where the single prefix had been inlined at four call sites.
