The editor does not resolve the same #id cross-script imports the runtime does 90

The runtime hook in src/script-hooks.ts genuinely resolves a bare #id specifier to the sibling <script id="…"> in the same document and loads it as a real module — this already works when the code runs. Reproduced the question directly instead of answering from memory: a document with <script type="module" id="yolo"> exporting a function, and a mycelium/command block doing import {YOLO} from "#yolo", runs fine under Node, but editor/check.ts against the same file reports ts(2307): Cannot find module '#yolo'.

editor/language-plugin.ts has nothing analogous to script-hooks.ts's resolver — TypeScript's own module resolution has no notion of "#id means the script tag with this id elsewhere in the virtual project," so it falls through to Node's reserved package-subpath-import syntax and fails. @volar/typescript does expose a hook for exactly this (createResolveModuleName, the same mechanism Vue's and Astro's language tooling use for their own custom specifiers) — this is a real, fillable gap, not a fundamental limit.
