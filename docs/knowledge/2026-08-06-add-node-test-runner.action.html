Add a node runner to the test family, and a sandbox for testing the command line 90 completed

A node case exports one default function and receives assert and a sandbox. The runner loads it with loadModule, the same function the engine uses for a command or an audit, so the rule for turning a file and a script tag into a module lives in one place.

An earlier pass wrote that rule out again inside the command, on the reasoning that a document should depend on the contract rather than on the engine. That reasoning does not hold here. language.template.html already imports the same function for its rules, and a second copy of a rule that has to match src/script-hooks.ts is exactly the drift this project names. The rule about importing only types applies to the contract, not to every helper the engine exports.

The sandbox is a documents tree of its own under the temporary directory, with this repository's templates linked into it. A symlink rather than a copy, for two reasons: a command lives inside a template, so a sandbox without them has no command to run, and a copy would let a test pass against a stale duplicate of its own subject. Every real import in a command script is a node builtin or a sibling in that directory, and the one import reaching further is a type import, which erases.

sandbox.mycelium(…) spawns the real command line against that tree. Slower than calling the exported function, and it covers what calling it would miss: how arguments parse, which path a command picks, how a document serializes, and the exit code. Each case gets a fresh tree.

Node documents run first and alone, so a repository whose tests all live there never starts a browser and never fetches a driver.

The first node document tests three claims about the knowledge commands: that add dates a bare slug, that it refuses a slug already carrying one, and that link writes the edge into the file named first. That last one is the direction the instructions warn about, and getting it backwards runs without complaint.
