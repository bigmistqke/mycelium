Let a link command compute its href from the same base it resolves files against 90 completed yes

The engine precomputes args.href for any invocation carrying two positional arguments, resolving both against docs/. Every link command resolves its own arguments against a subdirectory instead, so the two bases disagree and the href is right only when both files sit in the same directory.

Fixing it unblocks two things: an edge that points outside its own family's directory becomes reachable by the CLI, and language link starts working between terms/ and rules/.
