link mangles a target outside its own family's directory 90

knowledge link builds the href itself, prefixing ./ to the <to-file> it receives. Passing a path that leaves the knowledge directory writes href="./../templates/knowledge.template.html". And unlink computes the same wrong href, so it removes what link just wrote and never touches the hand-authored edge that prompted the correction.

One such edge exists. 2026-07-23-template-series-built.outcome.html points at ../templates/knowledge.template.html, and a person wrote it by hand. The commands cannot express that edge, so they cannot repair it either.

This blocks closing the relation vocabulary. Two edges carry relations no list names, and retargeting one of them needs a command that can address a file outside knowledge/. Declaring that an edge must carry data-rel costs nothing and waits for none of this, so the schema takes that step now and leaves the values open.
