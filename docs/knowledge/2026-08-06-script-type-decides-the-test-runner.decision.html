A test case's script type decides which runner opens it 90 active

Node tests and browser tests needed telling apart, and an earlier sketch gave a case data-needs="layout" to say so. That attribute would have restated something the document already carries.

A script's type inside a document already says where it runs. The mycelium/* prefix marks a script that only ever loads under Node, which is exactly what permits TypeScript in one, and src/script-hooks.ts and the editor plugin both read that prefix. So a case carrying mycelium/test is a node case and one carrying text/mycelium-test is a browser case, and the command reads the kind straight off the case.

Two things follow that a separate attribute would not have given. A case cannot claim one runner while carrying the other's language, since the type is the same fact in both places. And the rule needs no explanation of its own, because it is the rule the project already applies to every embedded script.

A document holding both kinds has no single answer, so an audit rejects one. That costs nothing: a node case and a browser case share no state, because each gets its own sandbox or its own page.
