Enforce bolded paragraph openers, and let a rule see markup 88 completed

139 bolded paragraph openers removed across 70 files, and the guide describing the habit became a rule that gates. Verified by injection: a bolded opener added to another document is reported by name and fails the run.

We could not write the rule under the old contract. A check received text, and text has no markup, so a rule about a bolded opener could see nothing. The alternative was to make it an audit, which would have put one rule of house style in two homes.

So a check now receives the text and the element it came from. Rules that read only text ignore the second argument, and lint passes nothing for it, which is correct: text arriving on standard input has no document behind it, so a markup rule finds nothing in a commit message.

The self-test found the real gap rather than a typo. It fed each rule its own examples as bare strings, so every markup rule would have reported that it cannot decide its own examples. Both examples are now passed as text and as the element holding them, the same pair the corpus supplies.

One consequence needed handling. A rule querying the document directly would reach a code block, a recorded user message, and its own failing example, none of which any rule may touch. The corpus pass now hands over a copy with those removed, so the decision about what is off limits stays with the thing that knows what a document is instead of being repeated in every rule.
