A patch is information with nowhere to land 90

The failure this family exists to prevent has a shape. Somebody starts with a clear abstraction, writes it down, implements it, and then meets behaviour they did not want. What happens next decides everything: a patch absorbs the surprise at the lowest altitude, and the next patch lands on the first.

A patch is what information does when it travels up and finds nowhere to land. Nothing states what should hold, so the surprise has no address, and the code takes it as a special case. Each one reads as reasonable on its own. The accumulation is the part nobody sees, because no statement exists for the code to have drifted from.

So the canon treats reality as the lab where an abstraction meets what it claimed, rather than as noise around it. Behaviour the chain did not predict is evidence about the layer above, and it lands somewhere: on a behaviour that says the wrong thing, or on an axiom that never held. An axiom carries a confidence for that reason, instead of standing as a decree.

It also sharpens what an ungrounded axiom is. An axiom reaching no behaviour is not merely unused. Nothing beneath it can push back, so nothing can falsify it, and grounded is a check for contact with the lab.

This session ran the pattern in miniature. A citation notation this project took from another test framework met two surprises, and each one drew a patch: a walk over tests rather than comments, then a read of raw trivia rather than the prose view. Changing the abstraction deleted both patches, the machinery under them, and the class of failure they came from.
