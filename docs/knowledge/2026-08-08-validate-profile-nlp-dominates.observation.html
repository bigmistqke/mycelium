Validate spends forty percent of a run on one audit's natural-language parse 90

A full run takes about twelve seconds. Engine boot accounts for 1.4 of them, parsing 620 documents for 1.9, and prose-follows-the-language for 4.2, of which 0.9 is loading retext and its plugins. Every other audit together comes to under a second.

The surprise is which half is cheap. Validating all 1092 instances against their templates costs 0.29 seconds, and discovering them costs 0.26. The schema check that looks like the point of the command is a fortieth of it.

Inside the language audit, the natural-language parse is the cost rather than the TypeScript one. Reading 462 comments out of 90 script blocks and 17 source files takes 0.38 seconds; running retext over the same corpus takes 2.9.

A cache within one run would save nothing, which a measurement settled before anybody built one. Of 1080 texts the rules read, 1072 are distinct: eight repeats, 1440 characters out of 1,035,382. Only one rule uses retext and it reads each text once, so there is no fan-out to deduplicate, and the document parse already happens once and gets shared.

What remains is a pre-filter, since retext-passive can only fire on a form of be or get before a past participle. Skipping a text with no candidate word would mostly help the short comments. It also carries the failure this project keeps meeting: a filter stricter than the rule makes the rule go quiet, and an absence reads the same as a clean pass.
