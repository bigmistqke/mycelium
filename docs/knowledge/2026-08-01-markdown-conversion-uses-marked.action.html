Replace the hand-rolled markdown-to-HTML conversion with marked 90 completed

The hand-rolled paragraph/list/heading/inline-span converter in markdownToHtmlFragment already needed one correctness patch (the list-continuation-line bug) on the first real document it ran against. That is the expected failure mode of approximating a well-specified format with a handful of regexes: each real document finds the next construct it does not handle — a nested list, a blockquote, an escaped asterisk, a reference-style link — one bug report at a time.

Replaced it with marked, added as a dependency: the whole function is now marked.parse(markdown, { async: false }). This is the same tradeoff this project already made once, for the same reason — retext/retext-passive is "the first rule here to import a library," accepted because hand-rolling grammatical passive-voice detection was not practical. Markdown parsing is the same kind of problem: well-specified, widely solved, and worth a real implementation rather than a repeatedly-patched approximation.

Verified against a fixture combining a wrapped list item, a nested list, and a blockquote — all three silently mishandled or unsupported by the previous version — and the audit/lint pipeline reports exactly the real violations in that fixture, nothing spurious. pnpm mycelium language lint on README.md and CLAUDE.md, pnpm validate (792 checked, 0 fail), pnpm typecheck, and pnpm check-scripts (175-diagnostic baseline) all stay exactly where they were.
