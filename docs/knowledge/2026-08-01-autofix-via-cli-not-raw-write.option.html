Route an autofix through the family's own CLI update commands, not a raw file write 60

For a corpus document (a knowledge/spec/plan/language entry), a verified fix should go through that family's own update --detail - (or equivalent), the same write path every other change to that document already goes through, rather than a direct file edit. This keeps a model's fix subject to the same validation, reindentation, and unchanged-file skip every other write already gets. A file with no such family (README.md, a source comment) has no CLI verb to route through, so a direct write is the only option there.

 a write-path option for this goal
