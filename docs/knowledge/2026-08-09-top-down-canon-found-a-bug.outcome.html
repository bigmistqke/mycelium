Writing the behaviours first found a bug seventeen passing cases did not 85

Eighteen behaviours produced eighteen cases, one each. On the ratio alone the layer looks like ceremony, and this pass exists to be able to report exactly that.

The ratio is not the finding. Seventeen cases passed on the first run, and the eighteenth failed: cutting a comment that trails code took the newline with it, so const a = 1 // note and the line below it became one line. Anything autofix touched that way stopped saying what it had said.

That case exists because a fix changes only what it reported came first, and reading it against cutRange raised a question the code had never faced. A suite growing out of the code would have covered the widening that works and never thought to try the other one.

So the behaviour layer earned its place here by what it made somebody ask, not by how many cases it produced. One bug in one command is thin evidence; the next subsystem to go through this tells whether it repeats.
