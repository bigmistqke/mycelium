Give the CLI a real validate command, so the roster stops naming one that does not exist 85 completed

src/run.ts printed audits (run by mycelium validate; any failure exits non-zero) above the audit roster, and no such command existed. Running it produced no command host found for "validate", because run.ts resolves every identifier to a *.template.html or *.command.html file and validation lives in neither.

The line drifted for the same reason the roster below it does not: the roster reads itself off the command scripts, while this header is a string. It named the wrong entry point from the day someone wrote it.

Rather than correcting the string, this makes the printed text true. validate becomes a command run.ts dispatches before it looks for a host file. validate.ts exports its run as a function, and its direct invocation sits behind import.meta.main so importing it no longer starts a validation run. The usage block names it too, so the roster advertises it rather than only mentioning it above the audits.

Two entry points existed before this, pnpm validate and pnpm mycelium. The validate script is now gone from package.json, leaving one way in, and every living reference moved to pnpm mycelium validate: the Pages workflow, CLAUDE.md, both README files, and plan.template.html. Plans, specs and nodes keep the old name, recording what was true when someone wrote them.

Validation belongs to core in a way a family's command does not, so naming it there puts no document type into the engine. The engine still knows nothing about a goal or a spec, only how to check whatever declares conformance.
