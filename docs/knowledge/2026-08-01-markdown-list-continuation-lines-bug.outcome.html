markdownToHtmlFragment silently misparsed a list whose items wrapped onto a continuation line 90

Found while checking CLAUDE.md against the new .md coverage: a numbered list whose third item wrapped onto a second line with no marker of its own (a normal thing to write) failed the check lines.every(l => MARKER.test(l)), since that one continuation line has no marker. The whole block fell through to the plain-paragraph branch instead of becoming three <li> elements, so paragraph-length counted a 3-item list as one 7-sentence paragraph, and sentence-length measured across item boundaries that should never have merged.

Fixed by requiring only the first line of a block to look like a list item; every following line either starts a new item (if it has its own marker) or joins the item above it. This is a real correctness fix, not specific to CLAUDE.md — any document with a wrapped list item was affected.
