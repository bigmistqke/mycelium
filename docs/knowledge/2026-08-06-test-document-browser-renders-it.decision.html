A test is a document, and a headless browser renders it rather than framing it 85 active

A test document runs its own cases. The browser only renders. It opens the file over file://, the page fills in its own results, and the CLI reads them out of the same test-status fields a person reads. The protocol is the document.

The harness this replaces had two of everything. A person opening a figure test and a build checking one would run different code, and the two drift apart. Here they open the same page.

Waiting until no test-status reads PENDING also carries async for free. A figure case waits for a frame and then for ResizeObserver, and no case ever declares itself async or hands a promise to a harness.

Past a deadline, a case still reading PENDING has failed. A thrown error writes FAILURE, so PENDING at the end means the script hung or the page never loaded its subject. The enum keeps three values and TIMEOUT never joins it.

The two kinds of test then divide by what each one touches, not by what it needs to measure. A node-test reaches the filesystem, spawns commands and imports src/*.ts, so no browser can host it. A browser-test reaches a rendered page, and whether a person or the CLI opened that page changes nothing about it. happy-dom leaves the test story and stays what it already is: how validate parses documents.
