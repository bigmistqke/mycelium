A boundary is real only if crossing it hurt 68

Architecture is not the boxes. It is the set of constraints a system actually defends. And a constraint is only real if breaking it had a consequence.

That is testable against history rather than against the code. Find the changes that crossed a claimed boundary, then look at what happened next. Reverted within a day, hotfixed, argued about for forty comments: the boundary is load-bearing. Crossed constantly with nothing following: it is decoration, drawn once and never enforced.

What this gives that static analysis cannot is the gap between the architecture people say they have and the one the system defends. That gap is usually the most interesting fact about a codebase.
