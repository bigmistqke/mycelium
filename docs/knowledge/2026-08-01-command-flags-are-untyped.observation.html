Nothing types a command's flags, though the template already declares part of that contract 65

src/api.ts types a command's args as ParsedArgs, an index signature: { _: string[]; [key: string]: string | string[] }. So args.title has type string | string[] inside every command, and no command states its own flags in types at all. The JSDoc above each export carries that contract in prose instead, and --help prints the very same comment.

Two ways to close that gap, differing in where the declaration lives:

  • Make CommandContext generic over an args shape, so each command writes its own. This types the function body and nothing further, since Node strips the annotations at run time and neither --help nor flag validation can then read them. It also restates what the template already says.
  • Derive the args type from the <template> shape. <spec-status required enum="draft approved implemented"> already states that flag's contract exactly, so one declaration could drive the type, the help text and the check together.

The second path only reaches flags that correspond to fields. spec add also takes --file, a slug no document ever holds, and --body, one blob covering four rich fields at once. Those still need a declaration of their own, so derivation shrinks the duplication rather than removing it.
