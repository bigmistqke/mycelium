Build the test family: a schema, an in-page runner, and a WebDriver command 90 completed

Four pieces. test.template.html declares test-doc and test-case, carries two audits and hosts the command. test.element.js runs every case in the page. Two documents under docs/tests/ test the figure engine.

The schema holds test-status at a single value, PENDING, so a document on disk can never claim a result. The runner writes SUCCESS or FAILURE into the live page and mirrors each into data-verdict, which is the only thing the stylesheet reads, since CSS cannot select on text.

The command knows nothing about cases, fixtures or assertions. It opens a URL, waits for no field to read PENDING, and reads the fields. Everything a test means lives in the page, so the document a person opens and the document a build gates on run the same code.

Both audits read the document rather than its rendering, which is the only kind of check that works here. One holds every case to carrying a script, the other holds every test document to loading the runner. Each catches an authoring mistake whose other symptom arrives at the deadline.

test run resolves a chromedriver against the installed Chrome and caches it under node_modules, or uses CHROMEWEBDRIVER where CI already provides one. A failing case leaves a screenshot of its own fixture beside the document.
