language lint now takes either - (unchanged: stdin text, no document, so a rule about markup finds nothing, correctly) or a file path. A .html path is parsed into a real document and stripped of protected elements, matching what the corpus audit does. Anything else is treated as markdown and run through a new, deliberately minimal markdownToHtmlFragment: a <p> per paragraph so paragraph-length can count sentences, a heading and each list item on its own line so they do not run into a neighbor, backtick spans become <code> so they are excluded the same way a real <code> tag is, and **bold**/__bold__ becomes <strong> so a mini-headline opener is a real element the same rule already looks for. Not a markdown renderer — links, tables, and nested lists stay literal text.
