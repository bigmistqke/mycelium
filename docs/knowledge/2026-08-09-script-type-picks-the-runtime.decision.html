A case's script type picks its runtime, so nothing needs one runner per document 90 active

A node case carries mycelium/test and a browser case carries text/mycelium-test. The label already sits on the case, so the question of which runtime hosts it has an answer per case and needs no answer at any larger scope.

The rule that a document's cases all run in the same place came from the command reading a kind once per file and opening the whole file one way. That is a property of the runner rather than of the corpus, and the audit enforcing it goes.

The first subsystem to need both is the one this change lands in. The chain canon holds three checks a sandbox can run and two drawing claims that only a browser can settle, since the disclosure the drawing builds exists only once a page runs.

One cost, and it needs saying. A browser document reports itself, so a person opening a canon holding node cases would watch those sit at PENDING forever. The page runner has to leave a case it does not own alone and say so, rather than letting it read as still working.
