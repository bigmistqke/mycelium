Nothing wants them yet. The rule that prompted the whole question needs only whether its prose sits above a named thing, and the tagged context already carries that.

Deferring costs less here than it usually would. The expensive move was going from positional arguments to an object, and adding a field to an object later breaks no rule and no call site. So there is no reason to add them while the code is open.

Two reasons against adding them at all. The audit's design is that the engine brings text to a rule rather than a rule reaching for things, and a whole file invites reaching. And a rule is a short script in a document, so putting a compiler tree inside one is why subject came back as { declares, name }.

The trigger, stated so nobody has to rediscover the question. When a rule needs something about its subject that those two fields cannot carry, widen the subject with plain data. Pass the tree only when the thing genuinely cannot be described without one.

The likely next caller is a rule checking that a doc block documents every parameter, and it wants a list of names. That is plain data, so it would widen the subject and still not need the tree.
