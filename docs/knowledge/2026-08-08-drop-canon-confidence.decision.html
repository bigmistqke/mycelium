Drop confidence from an axiom, and let the graph carry how the canon changed 85 completed

An axiom carried a number from 0 to 100 saying how far to trust it. Nothing read it. Across the canon the eleven values sat between 80 and 95, all written in one sitting, and not one moved afterwards. The same field on a knowledge node shows the pattern at scale: three values cover 305 of about 480 nodes, and the only code touching it checks that it parses as an integer.

The deeper fault is the shape rather than the discipline. The field existed to tell a principle somebody committed to from one an agent inferred by reading code, which is a question about kind. A magnitude cannot answer it, and no care in picking the number would help.

The family had already sorted itself on the axis that settles this. A knowledge node carries a date because it records a moment, so a confidence belongs to it the way a verbatim prompt does: part of what happened, and updating it would falsify the record rather than improve it. An axiom carries no date because it records a standing claim. Hanging a number frozen at the moment of writing on the one type that refuses moments is the whole inconsistency.

So the number goes, and the graph carries the history instead. A decision that establishes or revises an axiom is a knowledge node, dated, with the prompt that prompted it. Reading which axioms anybody actually decided means reversing those edges, which is derived rather than declared and needs no field on the axiom at all.

The knowledge field stays. It is coherent where the document is a snapshot, and only incoherent where the document claims to describe the present.
