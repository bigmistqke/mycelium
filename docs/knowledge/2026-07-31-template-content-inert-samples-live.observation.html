A script inside a template declaration is inert; the same script in a sample instance is a live audit 90

validate.ts discovers audits with querySelectorAll('script[data-audits]') over every document. A <template>'s content is a detached fragment and is not in the document tree, so a script written inside a type declaration is never found. Confirmed by probe: a declaration carrying data-audits="inside-template-declaration" produced no such audit.

A sample instance is different. It is a real element in the document, so its script is discovered and does run against the corpus. Only the audits' input excludes templates/; discovery does not.

This decides the shape of the worked example every family carries. The sample template-audit must have a script, because the schema now requires one, and that script must omit data-audits, or the documentation would silently register a real audit that runs on every build.

The result is a fixture that is inert and is also the counterexample: a template-audit that validates and never runs is exactly the hole the schema cannot close. The same asymmetry that forced the over-long title fixture to be shortened works in the other direction here, because audits skip templates/ and so the sample can be a counterexample without failing the build.
