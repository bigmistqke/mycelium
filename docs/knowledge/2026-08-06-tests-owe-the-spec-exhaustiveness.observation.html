Tests owe the spec exhaustiveness, which no citation can show 85

A citation from a test up to a spec rule says one test exists for that rule. It says nothing about the rule's other behaviours, and a rule with six behaviours and one test satisfies every structural check you can write over links.

What the method actually asks is the opposite direction: every behaviour a rule states has a test that reaches it. The spec is the list, and the tests have to exhaust it. Miss one and the implementation is free in that region, which is the region a bug lives in.

This puts real weight on the spec. A rule written as one paragraph of prose has no countable behaviours, so nothing can say whether the tests exhausted it. The behaviours have to be separate, addressable things before exhaustiveness means anything at all.
