Hand audits a filesystem instead of parsed documents, and wire one rule end to end 80 active

A tracer rather than the whole design. Audits receive a read-only filesystem rooted one level above docs/, so src/ is reachable and a language rule can eventually read code comments. The root stops there rather than at the repository root, because this project is heading toward being only v4, and monorepo support is a later question.

The three existing audits keep their bodies and gain one line each to build the document list they used to be handed. They cannot import a shared helper for it: each audit also runs in the browser demo through a data: URL import, which has no base to resolve a relative import against. That constraint is already recorded in the template as the reason extractGraph is duplicated rather than shared.

One rule gets a real check: rejected words, chosen because the corpus was cleaned this morning and it has nothing to catch. So the gate is green from the first run and no migration is needed to turn it on. Every later rule is one commit plus its own cleanup, cheapest first.
