A shared snippet is a file, not an embedded block, so no script type is added for one 85 active

A type reserved for shared snippets was considered and dropped. docs/templates/shared.ts already is one: TypeScript, on disk, imported as ./shared.ts by three command blocks. A relative import out of an embedded script resolves because the synthetic module URL the loader mints sits beside the real HTML file, so nothing new is needed to reach a file.

A new type would cost the engine an exclusion, the language server a mapping and a reader a concept, to reach code a plain file already holds without any of them.

The line it draws is where the next snippet goes. What the engine discovers lives in the document; what is merely called can live in a file. A command, an audit and a rule are declared by type and found by a selector, so a document has to hold them. A helper is only called.

What this measures is how little the embedded form was carrying. #extract-graph at knowledge.template.html line 649 is the only author-written #locator import in the project, so moving that one snippet to a file leaves the form with no users. The engine's own <file>#<locator> path is unaffected and stays, since it is how every embedded script is loaded.
