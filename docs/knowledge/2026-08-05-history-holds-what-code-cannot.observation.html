History holds three things the current code cannot: dead alternatives, scars and eras 78

Dead alternatives

The options that lost are the most useful nodes in any decision graph, and by definition none of them are in the current code. They are all over the history: reverted commits, pull requests closed unmerged, issues closed as wontfix, branches that stopped.

Recovering them means a newcomer asking why we don't just do X gets the pull request where someone tried X and how it died, instead of a shrug. No documentation practice survives long enough to record this. History records it without anyone trying.

Scars

Odd-looking code is either a scar or rot. A scar fixes something that actually happened. Rot is code nobody understands any more.

In the source they look identical. Only the history separates them, because a scar has an incident behind it and rot does not.

Eras

Codebases come in layers: before the rewrite, after the framework migration, after the outage. Dating each region to an era says which rules held when someone wrote it.

Two regions that look inconsistent often are not. They come from different periods, each one consistent with the rules of its own.
