Validate is a command document, not a verb the engine names 85 completed

Making mycelium validate real had two shapes. The first dispatched validate inside src/run.ts before it looked for a host file. That worked and cost something quiet: the word became reserved, so a family named validate could never resolve again, and core named one command it could not read off a document. The engine's whole claim is that it knows the protocol and nothing else, and this was the first exception.

The second declares it as docs/commands/validate.command.html, the suffix that already means commands, no document type, the same as explore.command.html. Core goes back to naming nothing. The roster picks the command up on its own, because printRoster walks command hosts, so the audits header that has always read run by mycelium validate is finally true without anyone writing a usage line by hand.

One rule in core made it possible. A host may export a default, which runs when no subcommand follows the host name, so mycelium validate works rather than mycelium validate validate. A flag in that slot belongs to the default too, so mycelium validate --dir x parses as one invocation. A host without a default still prints help, unchanged.

This trades a hardcoded command name for a general rule, which is the trade the engine keeps making. What it does not buy is independence from src/: the command imports validate from src/validate.ts and calls it. The document declares the command, never the implementation, which is true of every other family too.
