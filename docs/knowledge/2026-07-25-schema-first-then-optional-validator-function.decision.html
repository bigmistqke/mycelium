Generic schema check runs first; hand-written validator functions become optional 70 completed

The generic schema check runs first — required/pattern/enum/allowed-fields read off the template. A hand-written validator-function becomes optional, additive validation only, for logic the schema vocabulary can't express.

I reviewed all seven current check() functions, the six knowledge-* types plus spec-doc. Every rule in every one of them is already expressible via required/pattern/enum plus the field list itself: required fields, confidence's 0-100 range, status's enum, the "optional field present but empty" rule, the unexpected-extra-tag check. So in practice this resolves to full replace, and all seven hand-written functions go once their templates carry the equivalent attributes.

Construction loses nothing here, rather than policy losing it. A future type that genuinely needs logic beyond the schema vocabulary can still add a data-validates script, which the crawler would then run in addition to the generic check rather than instead of it.
