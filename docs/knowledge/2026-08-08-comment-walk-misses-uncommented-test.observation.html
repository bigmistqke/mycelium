Enumerating comments cannot find a test that carries none 90

The design for the citation reader said extraction already existed: commentRanges in code-comments.ts returns every comment alongside what it sits above, so one call hands an audit both the citation and the name of the test carrying it. That is true of every test somebody wrote a comment above, and it is the wrong shape for the check that matters most.

commentRanges enumerates comments. A test with a bare line above it produces no comment, so it never appears in the output at all — and a test with nothing written above it is exactly what cited exists to catch. Built that way, the check would have passed every test it could not see, which is the failure mode a check about missing evidence can least afford.

A probe caught it before the audit existed. Three tests in a sample source, one with a doc block, one with two comment lines, one with nothing: the first two came back and the third did not.

So the reading runs the other way round. testRanges walks test calls and attaches whichever comment sits inside each one's leading trivia, which reports a test with no citation as a test with no citation. Both functions share the one definition of what counts as a leaf test, so the two walks cannot drift apart on the question they both depend on.
