mycelium knowledge has no read-one-node command. list only prints one-line summaries — a bare [+detail] marker, not detail's content — so the only way to actually read a node's full fields is to open the raw HTML file directly.

This surfaced directly. Mid-conversation, reading nodes back required raw Bash and Read calls against docs/knowledge/*.html instead of any CLI command.

add, link, update, list and generate cover create, connect, mutate, enumerate and visualize. Nothing covers getting one node back in full: title, confidence, status, and especially the whole detail body.

Distinct from the gaps CLAUDE.md already names as known-missing (sync/publishing, config, diff/apply) — those are about multi-user sync; this is a more basic capability that seems to have been overlooked rather than deliberately deferred.

A natural fix: mycelium knowledge show <file> (or get), printing one node's full fields plus its outgoing edges in readable form.
