Move a check into the schema when the vocabulary already says it; otherwise leave it an audit 85 completed

Four audits exist. Two check one document at a time and two compare documents to each other. Only the second kind needs to walk the corpus.

title-length is a maximum length. The schema already has pattern, so it can be declared rather than coded. It moves.

hollow-action needs "at least one of detail or commit". The schema has no word for that, and adding one would grow the engine to serve a single type. The schema-first decision already provides for this: a type needing logic beyond the vocabulary keeps a script. It stays.

The rule is the vocabulary, not the kind of check. A check moves into the schema when the schema can already express it. Nothing is added to the engine to make a check movable.

Cost, stated rather than hidden: the audit holds the limit once and the schema holds it on each type's own title line, six times. Changing the number becomes six edits, and nothing checks that the six agree.
