Support a bare #id specifier as a same-file cross-script import, resolved against the importing script's own real file 75 completed script-hooks.ts's resolve() currently only recognizes '<path-to-html>#<id>' -- a same-file import (like generate's own extractGraph pull) has to spell out its own filename, which is redundant and breaks if the file is renamed. Add a branch for the case where the specifier is a bare '#id' with no path, and the importing module's parentURL is itself one of this mechanism's synthetic virtual-module URLs. Derive the real .html path back out of that parentURL and resolve against it. That is the convention href="#id" already has on the web: the same document by default, and a filename before the hash for a different one. Narrowly scoped to only fire when the parent is already one of our own synthetic URLs, so it can't swallow Node's own reserved bare-#-specifier package-subpath-import syntax elsewhere in the codebase. 7995999 main extends the #id addressing convention to a same-file shorthand shipped
