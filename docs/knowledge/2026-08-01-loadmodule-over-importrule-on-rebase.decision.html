Keep loadModule over the newly-written importRule when rebasing onto main 90 completed

Rebasing this branch onto main surfaced a real duplicate: main had independently fixed "a rule cannot import a library from a data: URL" the same day, by reusing loadModule, already present in src/utils.ts. This branch had fixed the identical problem by writing a new, near-identical helper, importRule, into a new file, docs/templates/load-rule.ts — same resolution shape, same locator logic, duplicated rather than reused.

Kept main's loadModule and dropped load-rule.ts entirely, carrying forward only what importRule actually added beyond it: marking a rule's script type="mycelium/rule", which is what makes the language server recognize it as TypeScript-eligible. Along the way, found and fixed a real bug in main's version: one of its two call sites resolved a rule's path against the literal string 'docs' instead of the filesystem's own root, which only worked by coincidence of the process's working directory.
