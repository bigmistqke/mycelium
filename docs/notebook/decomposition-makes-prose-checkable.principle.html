Decomposition is what makes a claim checkable against its code, not just tidier

The count of declarations answering more than one claim measures what has been claimed rather than what exists. A file nothing cites contributes nothing, so the number can rise as tagging improves, and it says nothing about code no tag has reached.

That is an argument for decomposing rather than against the number. A smaller piece has a more singular impact, and prose describing one thing leaves less room for a reader to decide whether the code still matches. The corpus grows in count and shrinks in ambiguity per piece.

It also decides whether a change can be checked at all. Reading a claim against a two-hundred-line function is a judgment nobody repeats reliably; reading it against six lines answering one claim is a question with an answer. The same split is what would let a diff say which claims a change puts in doubt.
