Let the schema check a list: validate every occurrence, and let a child slot name a type

Two reserved words beside required, pattern and enum. repeat validates every occurrence rather than the first, so required repeat reads as at least one. conforms names the type a child slot holds, and the validator descends into it.

The second one is the typechecking half. A container would declare what its children are rather than only that they may appear, which is what makes a figure's node rules bite on all twelve without each node carrying its own conformance.

Two costs to plan for. Switching it on for the plan family validates around thirty elements for the first time, and some will turn out wrong, so real cleanup follows. And a slot conforming to its own type would descend forever, so the descent needs a cycle guard.

One naming problem to settle first. The validator already reads data-validates on a script to bind a custom validator to a template, and today's scope work put the same word on a rule element for a different meaning. They do not collide in code, and one of them should change before more markup learns either.
