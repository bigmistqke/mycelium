Controlled English splits into a readability end and a logic end, and only the logic end resolves

Prompted by the question of whether writing to a strict language protocol (ASD-STE100 was the example) plus a project dictionary would make prose machine-checkable, and possibly resolvable — intent to implementation.

Checkable and resolvable are different properties, and the two ends of the controlled-natural-language spectrum buy different ones. The trade between naturalness and precision is monotonic; nothing sits at both ends.

  • Readability end (ASD-STE100). Closed dictionary of approved words, one meaning and one part of speech per word, sentence-length caps, active voice. Built in 1986 for aircraft maintenance manuals read by non-native speakers. Its conformance checkers verify dictionary membership, part of speech and sentence shape — never meaning. Remove the buffer passes clean with the referent still open. This end gives lexical determinism and no semantics.
  • Logic end (ACE, SBVR, Gellish, CPL). Attempto Controlled English translates unambiguously into Discourse Representation Structures — a syntactic variant of first-order logic — and onward into FOL, OWL 2, SWRL, RuleML and TPTP. It has a real toolchain behind it: APE the parser, RACE the reasoner (consistency checking and query answering), AceRules for forward chaining, ACE View for editing OWL 2 ontologies, and an OWL verbalizer going the other way. SBVR's Structured English drives rules engines. These are the actual intent-to-implementation precedents.

The failure mode is habitability: text that looks like English but means something else. The familiar surface hides where the language ends, so writers misread sentences they wrote themselves. The checker returns green, the human reads one thing, the resolver derives another.

An alien syntax does better, because it forces the rules to be learned rather than guessed. Any tooling here has to show the derived reading back, not just a pass/fail — which is exactly what ACE's verbalizer and editor exist to do.

The limit: ACE resolves to logic, not to code. Logic to implementation is program synthesis, tractable only where the domain is already narrow. Every working CNL deployment is narrow-domain with a domain-specific dictionary — aviation procedures, business rules, ontology authoring.

The dictionary is the whole mechanism, and dictionaries do not generalise. So the test worth running is not write the docs in a controlled language but take one narrow slice, write its dictionary, see whether a resolver falls out.

This project already has a small controlled language and has not named it as one. The six data-rel labels are a closed dictionary with fixed semantics and a documented minting procedure for extensions, and validate is already a closed-schema conformance checker. The open design question is scope: controlling the fields that carry traversal load (titles, edge labels) is cheap and additive, while controlling reasoning prose collapses the narrative layer into the structural one and buys the habitability problem in exchange.
