Propose a check for a line comment documenting a declaration, once the count reaches zero

Three corrections in one session is the argument for a check. The reader already answers the question: commentRanges reports what a comment sits above and whether it opens with a block marker, so the check is a filter over something that exists.

Not yet, and the order matters. The citation design learned this already: a gate arriving red teaches people to skip it, and 108 findings on the first run is red. The tags landed before that audit did, and the same order applies here.

A file header is the case that needs deciding first. It sits above the first declaration and binds to it, so a check would report every file in the corpus for a comment that is about the file. Either the check exempts a comment before the first declaration, or a file header stops being a comment and becomes something else.
