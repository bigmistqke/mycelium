Propose an axiom: read a document with a parser, never with a pattern

A candidate for the root canon, since it would govern every subsystem that opens a file rather than one of them. Roughly: a tool that reads structure uses a parser for it, and a pattern that recognises structure is a bug waiting for a file somebody formatted differently.

The reasoning an axiom would carry has two halves. A pattern encodes an assumption about the shape of the text rather than the shape of the document, so it answers a question it was never asked. And it fails quietly: a rename that matched half of what it should have matched produces a file, not an error.

What it would rule out is narrower than it sounds. Reading a value out of a line is fine, and the comment reader already matches a tag inside prose that a parser has handed it. What it rules out is deciding what an element is from how the text around it looks.

Left as a proposal rather than written, because an axiom needs a behaviour beneath it or grounded reports it as a principle nothing derives from. Writing it means finding the subsystem that answers for it and the check that could fail.
