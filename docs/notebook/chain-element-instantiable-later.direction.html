Leave the chain page's code a program for now, and make it instantiable when a check needs it

The page's code runs as a program bound to three ids in the document it draws. A check runs against a fixture inside its own document, so it cannot build one of these and let the real code lay it out. Making that possible means the shape the figure engine already has: an element a fixture can hold, taking its data from a child rather than from a lookup by id.

Not now, and the reason is proportion rather than difficulty. Every change this page has had shipped verified by generating it and looking — the depth columns, the declaration boxes, the header that survives scrolling. The under pane gets the same treatment.

The under-pane spec claimed a browser check would cover the scroll arithmetic, which was a standard invented that afternoon and met by nothing else in the file. The claim came from the fold having just made browser checks possible at all.

What would earn the restructure is a fault that looking does not catch. A wire drawn at the wrong offset is the most visible failure this page can have, so the arithmetic is not it. Something quieter — a selection that lights the wrong set, a pane showing another node's reasoning — would be.
