A history-deriver is another consumer of the engine, not a fork of the project

The first reading of this idea called it a fork. The grounds were that the graph's value comes from live capture: verbatim prompts, decisions logged before anyone knows the outcome, confidence scored in the moment. Derivation produces none of that.

That confused this project's logging policy with what the engine does. The engine validates document shape and runs audits. It has no opinion on where a node came from.

A deriver reading git history stands in the same relation to it as validate does, or explore. Nothing about it changes mycelium.

 nothing here changes the engine, so the goal is an application of it
