A comment inside a block is a decomposition signal, and the citation rule makes it one automatically

A citation sits in a doc comment, and a doc comment declares what it belongs to. So a comment worth citing has to sit on a declaration, and a comment buried inside a block has no declaration to bind to.

The chain page produced the case. A comment described what a run of twenty lines built, and tagging it landed the citation on an if, which the reader named at-line-88 because there was nothing else to call it. Giving the block a name settled it: the comment became documentation of codeFor, and the citation named something a person can open.

The rule generalises past citations. A comment inside a block explains a step in a longer thing, and a step worth explaining is usually a thing worth naming. The comment then documents what it names rather than interrupting what it describes.

What makes this pleasant is that nothing enforces it directly. The pressure comes from wanting the citation to land somewhere with a name, so the design asks for the decomposition rather than a check demanding it.
