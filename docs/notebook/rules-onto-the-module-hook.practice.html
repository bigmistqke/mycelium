Load a rule through the module hook and give every rule script a type

Both callers go through loadModule in src/utils.ts and pass an absolute path, because they are rooted differently: the lint command holds a filesystem rooted at docs/, the prose audit one rooted a level above it. Filesystem gained a reader for its root, which was the only thing actually missing.

Two of the three rule files carried a bare untyped script, which a browser executes on page load. They say type="mycelium/rule" now, and add and update set it when they create one, so a new rule cannot go back to being untyped.

Checked by what it caught, not by what it did not: lint reports three violations across two rule files, the audit fails a planted violation and passes once it is removed, and a rule made through add is picked up and run.

Landed on loadModule rather than a rule-specific importRule helper this action originally wrote: rebasing this branch onto main found main had independently fixed the same problem the same day, by reusing loadModule, which already existed. The two did the identical thing through the identical mechanism, so the newly written helper was redundant and dropped in favor of the one already in the codebase.
