Three checks keep an intent-to-implementation chain honest: grounded, covered, entailed

An axiom is checked against the code. A chain is checked against itself, and the question is whether it is intact. Three checks fall out, and two are cheap.

Grounded

Every intent reaches something real. An intent with nothing under it is aspiration: stated, believed, never built. Mechanical to detect.

Covered

Every piece of implementation traces up to some intent. Code with no reachable reason is the rot from scars and rot, now with a definition instead of a feeling.

Also mechanical, and harsh in practice. Most codebases would light up.

Entailed

Each step follows from the one above it. The intent was X, the thing someone built was Y, and Y does not get you X.

That is where bad architecture lives. Not in code that breaks a rule, but in code that faithfully implements a step which does not serve its parent. No type system catches it. It is a judgement, so it is the expensive one, and the only one worth a model.
