A rule is a language-family convention, and core has never heard of it

A README draft listed mycelium/command, mycelium/audit and mycelium/rule as three script types the engine carries, which reads as though the engine knows what a rule is. It does not. mycelium/rule appears nowhere under src/.

Each of the three reaches core differently, and only one by name:

  • mycelium/command is the one script type core names, queried directly in src/run.ts.
  • Core locates an audit through its data-audits attribute, in both src/run.ts and src/validate.ts, so its script type never decides anything.
  • mycelium/rule is a convention inside language.template.html, and that family's own audit loads it. src/script-hooks.ts keys on the mycelium/ prefix rather than a list of names, on purpose, so a type it has never seen still loads as TypeScript.

So the layering holds and the README misdescribed it. Worth keeping straight, because the same three-way listing invites someone to add the next family's script type to core to match the pattern the document implies.
