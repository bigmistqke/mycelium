The notebook declares three types. Two share a shape, and the third adds the three fields an instrument needs: a question, the script, and the reading that script last returned. The template says so, and the validator enforces it.

The drawing carried none of them. Its payload named five fields — address, title, kind, prompt, detail — so an experiment reached the page as a title and nothing else, however carefully somebody had written it. The schema and the payload are two lists of fields that have to agree, and only one of them has a validator.

Nothing failed. Every audit passed on both sides of the gap, because each list is internally consistent and no check reads them against each other. The symptom surfaced only when somebody opened the pane and found it empty.

The same shape will recur on the next field any type gains. A payload built by naming fields cannot notice one it was never told about, so the gap is structural rather than an oversight — closing it means deriving the payload from the template, or checking one against the other.
