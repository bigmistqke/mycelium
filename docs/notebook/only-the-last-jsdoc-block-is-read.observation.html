TypeScript reads only the last JSDoc block before a declaration gates harness check github ci -> something wrong in deploy -> we want to have the knowledge graph we recently worked on deployed

Four functions in figure.element.js annotate themselves with one tag per comment, stacked:

/** @returns {Box} */
/** @param {Origin} origin */
/** @param {Element} node */
function boxOf(node, origin) {

Only the block nearest the declaration applies. The other two are ordinary comments, so origin arrives untyped and @returns never lands. The shape reads as though each line adds to the one above it, and it does the opposite.

How loudly this fails depends on which tag ends up last, which is why it survived three commits. Two of the four stacks lost a @param, and noImplicitAny named them. The other two lost only a @returns, and a dropped return type is an inference rather than an error — nothing said a word about those until fixing the first two brought the rest into view.

So the visible failure and the silent one differ by tag order alone. A convention that types a function correctly or not depending on which line somebody wrote last is worth replacing with the single block the syntax expects.
