Prior art for moving enforcement into the harness: Flue builds agents from hooks

Flue is an open TypeScript framework for durable agents, by the author of Astro, running on a harness called Pi. Its second version builds an agent out of hooks: the function returns its own instructions, and useAgentStart, useModel and usePersistentState compose what it does.

That first hook is the interesting one here. Every rule this project enforces lives either in a shell hook configured outside the repository, or in a validate run that fires once the work is finished. A hook a project writes for itself, and versions with its own documents, is where a rule such as "a family gets a spec before it gets a template" stops depending on somebody remembering it.

Skills answer a second thing. Flue loads a skill from a markdown file when a task calls for it, where this project's instructions load two hundred and fifty lines every session whatever the work is. The rules that fire in practice are the ones with a hook behind them, and the rest share a file too long to read closely.

Two parts do not carry across. Flue records a session as a durable stream that survives a crash, and a transcript is not this graph: a node here is a decision somebody chose to keep and link, not everything that happened. Reading the two as the same thing would retire the graph in favour of a log.

And Flue builds with Vite and deploys to a cloud runtime, against a project whose documents open from disk with no build step at all. That constraint is what made figure.element.js a classic script. The documents would not change, but the harness would bring a build this project has refused so far, which is a choice to make rather than to drift into.
