A leading question mark marks a schema attribute optional, since every declared one was mandatory

The reserved-word form built this morning reads any attribute on a placeholder as one the instance must carry. That covered its first caller, which wanted a required attribute, and left no way to describe a flag only some instances carry.

data-back on a figure edge is exactly that flag. Only an edge running against the flow carries it, and making it mandatory would put it on every edge and lose the point.

So a leading question mark on the placeholder's value marks the attribute optional, and the rest is still the pattern. data-back="?" permits it with no constraint, and data-back="?^(soft|hard)$" would permit it and close its values.

Nothing is ambiguous, because a regular expression cannot begin with a question mark. It quantifies nothing and throws, so no existing pattern can collide with the marker.
