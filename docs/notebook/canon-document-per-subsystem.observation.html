One canon document per subsystem, with root holding what governs everything

A flat canon/axioms/ directory put the figure engine's principles beside the ones about documents and gates, as though they were peers. The set that shaped one subsystem says nothing about the others, and pouring all of them onto one sheet buries the few that do govern everything.

The alternative considered and rejected was regions: a second vocabulary of scope names applied by hand. That is what link, do not tag already refused once, and it would need maintaining.

So a canon is a document per subsystem holding its own axioms and the specification its behaviours belong to, with root.canon.html for the axioms everything narrows from. Where an axiom belongs is readable rather than decided: cited from more than one subsystem means root, cited from one means it lives there.

Nothing about the checks changed, which is what said the layout was a reading concern rather than a structural one. A reader locates an instance by data-conforms-to wherever it sits, several conforming elements in one document were already allowed, and the three chain checks never cared about files. Only the commands moved.
