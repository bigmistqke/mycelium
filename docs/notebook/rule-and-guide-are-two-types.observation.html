A rule and a guide are two types, so the label cannot disagree with the mechanism

A rule that gates and guidance a person applies are different things, and reading a directory of both told you nothing about which was which. The obvious fix, a directory per kind, would have restated in the filesystem what derive enforceability from the check had just decided to derive: a file in rules/ with no script would be the same disagreement the deleted language-checkable field allowed.

Two types instead. language-rule declares <script required> and language-guide does not, so the label and the mechanism cannot come apart: a rule with no check fails its own template and the validator blocks it. The directory then follows the type, the way terms/ and rules/ already do, and carries no claim of its own.

This is why the earlier objection does not apply. Declaring something a machine can check is unsafe when nothing verifies the claim. Declaring a type whose schema requires the check is the verification.

The guard runs one way. The schema can require a script on a rule and cannot forbid one on a guide, because the closed-field rule inspects dictionary-* children and a script is not one. That is the attribute gap left open earlier today, and the audit covers it: a guide carrying a check is reported, since it would be enforcing something while filed as guidance.

Thirteen of the fourteen rules became guides, which is the honest count of how much of this dictionary is enforced. One rule carries a check.
