Axiom and specification share one family file

The axiom and the specification go in one canon.template.html, holding a template per type, rather than in a file each.

This is the convention already in place. knowledge.template.html holds six types and plan.template.html holds four, in both cases because the types only mean anything together. An axiom that adjudicates nothing and a specification with nothing above it are each half an idea; the chain is the object, and a family file is how this project writes an object with parts.

The family answered to derivation while this decision got made, a name tests cite, they are not nodes had already used in July. It became canon once the tags went on a page and read badly: derivation names the relation between one rung and the next, so the compound put two abstractions together with no picture behind either.

What this gives up: a file called specification.template.html announces the weight of the thing it defines, and canon-specification does not. The word carries that weight instead, spelled out and never shortened, which the term entry now records.

A subdirectory grouping the two was the third option. The engine would resolve it — findTemplateFile matches a suffix anywhere under the tree — but nothing else would read it, and a folder that groups for a reader alone is the split by subject that language.template.html avoided when it separated terms from rules by type.
