pkg.pr.new skips a package declaring itself private distribution

The publisher reads each package's own manifest and drops any carrying "private": true, printing skipping … because the package is private and moving on. It does not fail the run, so a workflow that publishes nothing at all still reports success.

That flag is the usual guard against publishing something by accident, and this project set it for exactly that reason. Continuous previews and that guard cannot both stand, so the flag goes and nothing running npm publish ever exists here to need guarding.

The --compact form of the install URL goes for a related reason: it resolves a bare package name, which means a name claimed on the registry. A project deliberately staying off the registry gets the owner/repo form instead.
