An audit becomes template-audit, part of the template vocabulary, not a family of its own

An audit is the protocol's, not any project's. Every project using this system wants audits; only this one wants knowledge-goal. So the type belongs with the machinery rather than beside the subject matter, which puts it in template.template.html — a file that until now declared no types at all, only prose and the generic validator.

The naming rule decides what it is called, and the reasoning that makes the name read correctly is the point. The prefix names the vocabulary a tag belongs to, so template-audit is "the audit tag from the template vocabulary", not "an audit of a template". It earns that prefix because it is only ever used inside other templates, never as a document of its own.

Fields are template-title and template-detail, plus a required <script>. Nothing else: data-audits and data-touches stay on the script where the engine already reads them, because a second home for the same value is the duplication that writing the title limit six times had just created an hour earlier.

No id either, for now. The element's name would be a second copy of data-audits, and nothing needs an anchor until a language rule wants to link to the audit enforcing it. Deferring beats designing around it.
