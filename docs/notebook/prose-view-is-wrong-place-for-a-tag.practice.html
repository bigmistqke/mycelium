A prose view is the wrong place to read a tag, and it fails by finding nothing

Two branches met and the citation reader went quiet. Every behaviour read as untested and every test as citing nothing. No check threw and no message appeared, because a chain holding no citations is a real state the audits report, and they reported it faithfully.

Neither change that caused it was wrong. formatCodeComment began dropping JSDoc tag lines, because a tag declares a type rather than saying anything a rule could ask somebody to reword. commentRanges already dropped a comment left holding no prose. A comment carrying one @specification line and nothing else meets both, so it left the reader's world entirely.

The fault was in the reader, which asked a prose-shaped question about something that is not prose. text exists for the language rules. A citation is a tag, so it has to come off the raw comment, and now does.

This is the second failure at the same joint with the same shape. The first was a walk over comments that could never see a test carrying none. Both read an empty answer as a negative one, and running the code found both: a probe caught the first, and for the second, two audits disagreed with a chain that visibly had a citation in it.

What it says about the design: a check reporting absence cannot also establish that it can perceive presence. data-expects covers that here, which is why each of these audits keeps a worked example that makes it fire.
