Compression is the deliverable: a derivation that emits four hundred claims has failed

The graph already holds most of this argument. Cheap capture does not produce quality, it scales whatever quality was already there, and at zero capture cost selection becomes the scarce thing. Derivation is the extreme case of both.

So the target is a small number. A codebase has maybe ten to thirty claims that constrain anything. Four hundred true claims is a failure, however true they are.

What is new is the division of labour that gets you there. The machine nominates candidates. A person promotes a few to canon. The machine then maintains those forever.

Ratification is the only scarce step, so it is the only thing worth optimising for. That needs two tiers which never blend, and the graph has no way to express them today.

 the size the output has to come down to before it is worth having cheap capture scaling existing quality is the same argument at derivation scale
