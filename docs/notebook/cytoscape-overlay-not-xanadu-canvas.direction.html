Overlay real knowledge-* elements on a precomputed cytoscape layout, not a Xanadu-style on-demand panel canvas

The v4/experiments xanadu exploration (v4-explore-canvas-rendering worktree) deliberately rejected a precomputed node/edge diagram in favor of an on-demand canvas of real document panels — see its own "Pursue a canvas of real document panels... not a precomputed node/edge diagram" decision. That call was for an explorer: open only what you click, no upfront layout.

knowledge generate graph is a different tool with a different job: a single static snapshot of the whole graph at once, which is exactly why it exists as a separate command from explore. That job still wants an upfront layout — so this keeps cytoscape's cose layout and edge drawing, and only swaps the node's own visual: the same trick the xanadu work found (the hyphenated knowledge-* tags plus knowledge.template.css render a full card with zero JS component) rewrites the "circle plus truncated label" node into a real card overlay.

Cards default to compact (title/confidence/status only, detail and prompt omitted) because a force-directed layout of 368 nodes with full detail inlined at all times would be illegible and slow. Clicking a card opens its full real markup — literally the node's own <knowledge-*> element with detail, prompt, and links intact — in a side panel, so the compact view defers the full html-node look by one click rather than dropping it.
