A check belongs beside the vocabulary it checks, not inside an engine that names it. 85

An audit sits in the template declaring the types it reads, and a command sits in the template whose files it writes. The engine discovers both by crawling for a script that says what it is, so adding a family adds no case to any dispatch table.

This is what keeps the engine free of an ontology. A checker that hardcodes the names of the things it checks can only ever check one project.
