An experiment shows the instrument it ran draft 2026-08-10

The drawing's side pane tells a reader almost nothing about an experiment. It shows a title and, where one exists, the prompt behind it. Both experiments in the corpus therefore read as a bare line of text, while an observation beside them carries paragraphs.

Two separate causes produce that, and fixing either one alone leaves the pane thin.

The first is that the page never receives the fields. An experiment adds three of them to the shape the other two types share — a question, the script, and the reading that script last returned. The payload the drawing builds carries an address, a title, a kind, a prompt and a detail, so all three go missing before the page loads. No amount of authoring reaches the reader.

The second is that neither experiment carries a detail. That field is already the last one the type declares, and it takes markup, so nothing in the schema stood in the way. The flag went unused, which is the same gap that once had eight entries stuffing their findings into the title.

Delivering all four fields then exposes a third problem. They arrive as one column of prose, so a reader cannot see where the question stops and the finding starts. An experiment has parts that play different roles, and running them together throws away the structure the type went to the trouble of declaring.

The cost lands on the type that can least afford it. An experiment exists so a number can recompute, and a reader who cannot see the question or the reading cannot tell what recomputed or whether it moved.

The payload gains the three fields, and the pane presents an experiment as four named sections rather than as prose.

The four already exist, so nothing joins the schema. The question is the research question, the script is the method, the reading is the data, and the detail is the conclusion. Naming them in the page is what turns four fields into a report.

They read in that order, which is the order somebody ran them. A prompt stays above all four and quoted, under the rule the pane already follows: somebody else said it, and everything under it answers it.

Each section carries a small header, and the header for the method doubles as the control that unfolds it. A separate label above a disclosure would say the same word twice, and the summary is already a line a reader clicks.

The method stays folded. Putting it second matches how an experiment runs and lets a reader see the shape of the whole report at once, while a thousand characters of code unfolded there would bury the finding underneath it. A reader came for the data and the conclusion, and opens the method to decide whether to believe them.

A section with nothing in it draws no header, so an experiment missing its conclusion looks unfinished rather than looking like a section that renders empty. The other two types show no headers at all, since one blob of prose needs no signposting.

Where the title and the question say the same words, the pane shows them once. A title earns its place by being short enough to scan in a column of boxes, and an experiment whose title grew into the whole question has stopped doing that job — but the pane repeating itself is the wrong way to complain.

The disclosure already exists, and the canon drawing opens a declaration's implementation through it. It hardcodes the word implementation, which is wrong for a script that measures the corpus, so its summary becomes a parameter.

Nothing here runs an experiment. The reading the pane shows is whatever run --record last wrote, and a page that recomputed on load would turn a probe into a build step.

The reading stays a plain string. Giving it structure, so the page could show that a number moved between runs, needs a second reading to compare against, and nothing stores one.

No conclusion field joins the type. The detail already holds the prose that reads a finding back, and a second prose field beside it would leave an author guessing which one to fill.

Whether a detail should become required on an experiment. Both entries lacked one, which argues the field is too easy to skip, but the same was true of every type before anybody wrote prose into them. A header that names the missing section may be pressure enough.
