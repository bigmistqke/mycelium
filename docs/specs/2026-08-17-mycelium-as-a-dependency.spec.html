Mycelium installs into another project: a package, a bare specifier, and a corpus the base command seeds draft 2026-08-17

This project grew as one checkout where the engine and the corpus sit beside each other, and nothing about that arrangement was ever a decision. Another project wanting the same tooling needs the engine from node_modules and a corpus of its own. Neither half survives that separation today.

The package declares itself private, carries no bin and exports nothing, so nothing installs it and nothing runs it. Twenty-one documents reach the engine through ../../src/api.ts, a path that holds only while the corpus is a sibling of src/. The engine resolves its corpus as ./docs against the working directory, which is the single tie that already works in somebody else's repository.

Releases go through pkg.pr.new rather than a registry. That publisher reads each manifest and drops any package marked private, printing skipping … because the package is private while the workflow still reports success. Its --compact URL form resolves a bare package name, so a project staying off the registry gets the owner/repo form instead.

A consumer's corpus lands at .mycelium/, and this repository moves there too so that both run the same shape. That rename has one quiet hazard. walkFiles skips every entry whose name starts with a dot, and fourteen call sites across five documents name the corpus with the literal string "docs", so each one would return nothing rather than fail and every audit would pass while checking an empty list.

Four changes carry this, and each one stands alone. The corpus moves, the package gains a shape, the documents reach the engine by name, and the base command seeds a corpus where none exists.

The corpus moves to .mycelium

One directory name serves both this repository and a consumer, so nothing has to keep two arrangements in step. Two constants hold the old name, src/run.ts where the engine resolves its root and editor/check.ts where the language server finds documents to check. Configuration holds the rest: the ignore file, the TypeScript project, and both workflows.

The ignore file needs care beyond a rename. It already lists .mycelium/, left over from a store that went in July, so moving the corpus there without dropping that line hands the whole corpus to git's ignore rules.

Audits stop naming the directory. AuditFs already carries root, and the corpus directory belongs beside it as the same kind of fact, so an audit reads a name it receives rather than one it repeats. Fourteen literals become zero, and the next rename touches one line.

The package gains a shape

The manifest drops private and gains bin, exports, files and repository. The bin entry points at a shim that imports src/run.ts, because Node 24 strips types on import and this project has no build step to add. exports maps ./api and ./utils, the two modules a document ever reaches for.

Nothing here runs npm publish, so dropping the private flag removes a guard against something no script does. The workflow publishes one preview per commit and consumers install from https://pkg.pr.new/bigmistqke/mycelium@<sha>.

Documents reach the engine by name

Every ../../src/api.ts becomes mycelium/api, and the same for utils. A bare specifier resolves through node_modules in a consumer and through this package's own exports here, so one string works in both places.

This repository depends on itself, with "mycelium": "link:.", rather than leaning on Node's self-reference. The link puts a real node_modules/mycelium in place, so the editor resolves the specifier the way a consumer's editor will, and pnpm mycelium runs the published bin rather than a path only this checkout has.

The base command seeds a corpus

Running mycelium with nothing after it looks for .mycelium/ and writes a seed when nothing is there, then prints the roster as it does now. A second run finds the directory and leaves it alone, so the command stays safe to run at any time. More may attach to that command later, and this is the first thing on it.

Seeding lives in the engine because a corpus command cannot bootstrap the corpus that would hold it. That is the one thing the engine has to know beyond its protocol, and it knows it as a directory to copy rather than as anything about what the copied documents mean.

What the seed holds

An instance names its own template by relative path and every-link-resolves opens that path, so every template a consumer authors against has to sit in the consumer's own tree. The seed therefore holds template.template.html with the schema vocabulary and the generic validator, the notebook, language and followup families with their stylesheets and scripts, and the language rules that give prose-follows-the-language something to enforce. It holds the command documents too.

Six links in those documents point at this project's own specs and notebook entries, which a consumer's corpus will not hold. Each becomes an absolute URL into the published site, so a reader can still open what the document cites and every-link-resolves stops caring.

Publishing to a registry, which the whole design exists to avoid. The three capability gaps waiting on the crawler stay where they are: a browsable published graph, grouping by branch, and exchanging patches between people.

A consumer's own instructions for an agent. This repository's CLAUDE.md teaches an agent how to use these commands, and a consumer needs something equivalent, but what shape that takes is a separate question from what installs.

Whether the seed carries agent instructions alongside the documents. A consumer installing the tooling gets no CLAUDE.md, and an agent that cannot read the rules will hand-edit documents the commands exist to write.

Whether this repository still publishes its corpus to a site once the corpus has a dot-name. The deploy workflow uploads the directory as an artifact, which should survive the rename, though a hidden directory reads as tooling state rather than as a website.

How a consumer upgrades. Command documents live in the consumer's tree after seeding, so a later engine release leaves those copies behind with no mechanism saying so.
