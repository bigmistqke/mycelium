A test cites a behaviour with an edge, not a tag in a comment draft 2026-08-08

The derivation chain's bottom rung was designed against another project's test framework. A citation is a comment carrying @specification, and a leaf test is an it(...) or test(...) call, which is what Playwright and the project that ran this methodology before both give you.

This repository has neither. A test here is a document. A test-doc holds test-case elements, each carrying a name, a status, an optional fixture and a script, and a node case exports one default function rather than calling anything named it. So the reader finds no test in docs/tests/ at all, and the two families pass each other by while both spelling a script type mycelium/test.

The tag notation has also failed twice, both times by finding nothing and reporting that as an answer. A walk over comments could never see a test carrying none. Then a comment holding one tag line stopped surviving the reading view, because that view drops tag lines and then drops any comment left holding no prose. Each time the audits reported an empty chain faithfully, and each time the only thing that caught it was a worked example built to make the check fire.

Both failures share a shape. The citation lived in text that another part of the system was free to reformat, and neither part knew the other was reading it.

A test-case carries its citation as an ordinary edge:

<test-case id="exits-non-zero-on-failure">
  <test-name>validate exits non-zero when an audit fails</test-name>
  <test-status>PENDING</test-status>
  <a data-rel="depends_on" href="../canon/specifications/validate.specification.html#exits-non-zero-on-failure">the behaviour this checks</a>
  <script type="mycelium/test">…</script>
</test-case>

Four things fall out of that, and none of them needs new machinery.

A case already has an id, so it already has an address. A violation names docs/tests/link-href.test.html#language-link-crosses-directories rather than a slug made from the test's own wording, which was the best a comment could offer and moved whenever somebody reworded the test.

every-link-resolves already checks that a link reaches the file and the anchor it names, and it learned to check the fragment for this chain's sake. A citation is now an ordinary link, so a citation pointing at a behaviour that no longer exists fails there, in the check that already exists for it.

depends_on is the relation, from the closed set every family shares. The chain's upward edges are already depends_on: a specification names the axioms it serves, an axiom names the one it narrows, and a case naming the behaviour it checks is the next rung of that same ladder. Nothing gets minted.

The reader stops parsing source entirely. It queries test-case elements and reads their edges, which is the same reading readCanon already does one rung up. So testRanges, the leaf-test definition it rests on, and the reading of comments in .ts files all go, along with the class of failure they carried.

This follows link, do not tag, which the project settled once already for a different reason and which applies here exactly: a link is a thing a reader can follow and a checker can resolve, and a tag in a comment is neither.

No authoring command. A citation is one edge on a case somebody is writing by hand anyway, and test.template.html deliberately has no add for the same reason: a test's substance is a fixture and a script, and neither fits on a flag.

Nothing here makes a browser case cite differently from a node case. The edge sits on the case, above the script, so the script type stays what it already means and decides only which runner opens the page.

Whether a case may cite more than one behaviour. The schema allows a repeatable edge and the reader accepts any that land, so today it may. Whether that is right is the same question the old design asked about one target per line, and neither has met a real case yet.

Whether cited should distinguish a case citing nothing from one whose citation resolves to an axiom rather than a behaviour. Both fail now, on the principle that a citation gets judged on where it lands. The second is the more interesting finding and currently reads the same as the first.
