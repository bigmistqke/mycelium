figure.template.html: a diagram that stays a document implemented 2026-08-06

A report needed a diagram of how a system fits together, and two forms went in before this one. Markup with every box placed by hand looked right and read back as nothing: its meaning lived in coordinates, so no query could find a node and no check could tell a real relation from a typo. Mermaid reads back and gives up the styling, and it invents a node for a name that resolves to nothing, so a diagram with a mistyped edge renders happily and lies.

That last failure is the one this project cares about most. A picture that renders, looks deliberate and says something untrue is worse than no picture, because nothing about it invites a second look.

The question is not which of the two is prettier. It is whether the picture is still a document once you have it: whether a node can hold a link, whether an edge names two things a check can resolve, and whether a reader can recover the structure from the source.

A figure is elements. figure-graph holds figure-node and figure-edge, a node declares the cell it occupies with data-at="row,column", and CSS grid places it. A cell is structure and a pixel is not: 3,1 means the same thing at any width, font size or theme, because the browser works out where that lands every time.

Connectors carry no numbers at all. figure.element.js measures the laid-out grid and draws an overlay, so no geometry ever reaches the file, not even generated. The script is a classic script rather than a module, because a document here opens over file:// and a module script cannot pass the CORS check at that origin.

Three kinds of edge, and each says which it is rather than being guessed at. A forward edge crosses the gap between two rows. A back edge carries data-back and runs in a column reserved for it, sized by the grid to hold its own label. A peer edge joins two boxes in one row, which the element reads off data-at.

Edges crossing one gap take lanes. Two may share a lane when they share a box, because a fork and a merge are one thing seen from either side, and otherwise only when their sideways runs never overlap. Edges landing on one box arrive at separate points along its top edge.

Labels live in the gap their own edge crosses and never over a box, stay inside the figure, and stack clear of one another. A gap too shallow for the labels crossing it grows until they fit, which is the rule an edge column already follows for the label inside it.

Four audits carry what the schema cannot: an edge names nodes that exist, an edge runs the direction it claims, and a peer edge reaches its neighbour without crossing a box. Geometry is not a corpus claim, so the drawing is tested instead, by documents in the test family.

No layout engine. A node says which cell it sits in, and a figure whose shape does not suit a grid has no answer here.

No routing. Two edges that share no box no longer share a lane, so they cross rather than appearing to meet, but nothing steers either around the other.

No authoring command. A figure's substance is its markup, which is the state knowledge and language both started in.

The schema checks one child of each kind and ignores the rest, so a figure with twelve nodes has one node checked. That gap belongs to the schema rather than to this family, and eleven plan documents lose the same way.

A peer edge's label sits above its row rather than on its line, because two neighbours leave only the column gap and a chip is wider than that. It reads as detached.

Crossings stay crossed. Whether they should is the next question a denser figure will ask.
