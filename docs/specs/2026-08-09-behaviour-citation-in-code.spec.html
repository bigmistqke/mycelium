A behaviour citation in code, so canon reaches past the file draft 2026-08-09

Canon reaches code through one edge. A specification carries specifies, and all eight in the corpus name a whole file with no fragment. The drawing renders that as one box per file, which is where this started.

A behaviour reaches nothing. Its template allows depends_on and no other relation, so a behaviour points up at an axiom and nowhere else. Nothing in the corpus answers which code answers this claim.

The cost arrives when a claim moves. Rewording a behaviour keeps every citation resolving, and the graph already admits nothing tells the citing cases they now check something the document no longer claims. The code has that same problem and no citation at all.

The tag

A doc comment on a declaration names the behaviour that declaration answers:

Its value is an address in the form every citation here already takes: a path from the documents root, then a fragment. The tag repeats where a declaration genuinely answers more than one claim, and a declaration needing that is a declaration worth splitting.

A doc comment, not a line comment

A doc comment declares what it belongs to. A run of line comments binds to whatever follows it, which is a different thing: the compiler hands a leading comment to the next node across a blank line, so the binding happens whether the author meant it or not.

That accidental binding is the smell. A note about the file, a reminder, an aside about the line above — each lands on the declaration underneath it and claims to describe it. Moving a function then carries somebody else's paragraph along.

So a comment about a declaration becomes a doc comment on that declaration, and a citation only ever sits in one. A note with nothing to bind to is either prose belonging in a document or a reminder that has finished being useful.

The citation points up

An earlier sketch had the behaviour carry specifies, aimed at an anchor inside the implementation. That points down, and a stored edge points up, because a hand-maintained reverse index rots invisibly.

Pointing up costs no new relation and no schema change on the canon side. A behaviour keeps the one relation it has. The code cites the behaviour the way a test case does, and which code answers a behaviour gets computed from the tags, like every other downward reach here.

Every declaration names the behaviour it answers

Nothing about the tag concerns exports. A doc comment binds to whatever it sits on, and an internal helper carrying a claim is exactly as worth addressing as an entry point. A file exporting nothing at all still answers behaviours, and figure.element.js answers twelve.

A declaration in a participating file names the behaviour it answers. One naming none has three fixes available: cite what it already answers, split it until each part answers one, or write the behaviour nobody had written down. The third is the valuable case, and the project this borrows from turned sixteen of them into real rules.

Nothing fails for want of a citation, and nothing gets exempted either. A declaration naming no behaviour is uncommitted, the check counts it, and the count is the point. That is how any works in a typed language: legal, visible, and a standing signal about where the guarantees stop.

Some code is honestly uncommitted. MODEL picks which model to ask and could pick another tomorrow, so it is a setting rather than a promise. Forcing a behaviour on it would buy a test that goes red when somebody edits the line and never catches a mistake.

One citation per declaration is the target. A function carrying five is doing five things, and the count names the decomposition worth doing. So the tag applies pressure on the design rather than only recording it.

This is the whole question mycelium exists to ask. A corpus where every declaration names its claim has an intent graph as dense as its call graph, and the code carries the reasoning rather than pointing at a document that holds it. One where a thousand lines hang off two citations has claims nobody can locate.

Scope comes from the corpus

A file participates when a specification names it. The eight specifies edges already declare which files belong to a subsystem, so scope gets read rather than configured. It grows when somebody writes a specification, not when somebody remembers a list.

A file no specification names is not ambiguous. It is not participating, and nothing about it is a finding.

The boundary has to sit somewhere a check can read, because partial coverage makes silence ambiguous. An empty result must mean nothing cites this rather than nobody got round to tagging.

What the check reports

Two findings fail. An address resolving to nothing is rot, which every-link-resolves reports for a document and cannot see inside a comment. A behaviour no code cites is dead, which grounded already reports for an axiom nothing reaches.

Two numbers get reported and fail nothing. How much of a file names a claim, which is the ratio this whole design exists to move. And how many behaviours each declaration cites, where a high one names a candidate for decomposition.

Both directions still get counted, and each shows what the other misses. From the claim, the count asks whether anything implements what the canon promises. From the code, it asks how much of what runs answers to anything at all.

A citation gets judged on where it lands, never on what carries it. A tag landing on an axiom is a finding for the reason a test case doing it is one: the code knows something no behaviour states. Judging the resolved address rather than the tag name is what makes a separate @axiom spelling unnecessary.

What the drawing gains

The implementation rank stops being one box per file. It becomes one box per cited declaration, sitting under the behaviours naming it, so a function answering six claims looks different from one answering one.

Selecting a behaviour then lights the code, which is the blast radius the chain draws for every other layer already.

Order of arrival

The tags land before the audit. A gate arriving red teaches people to skip it, and this project watched that happen to a gate that reported failures and exited zero for weeks.

Eight files bound the retrofit. The audit joins validate once every count reads zero.

Nothing here detects a wrong citation. A tag naming a behaviour the code does not implement resolves fine, and reading the two together stays a person's job. The graph records that same limit for a reworded behaviour.

The specifies edge stays as it is. This adds a layer beneath it rather than replacing it, since naming the files a subsystem answers for is still worth saying in one place.

Converting the corpus's line comments to doc comments is a separate pass. This one puts citations in doc comments and leaves the rest where it sits.

Whether the decomposition count should ever fail rather than report. A ceiling of one citation per declaration is the honest reading of the rule, and no code here meets it yet.

What a type owes. A shape makes no promise on its own, and the functions using it carry the claims, so an interface may be permanently uncommitted by kind rather than by accident. The count will show whether that distinction earns a rule.

Whether rewording a behaviour should fail its citers until somebody re-confirms them. A stamp recording that a citation got read against the current wording is stronger and more annoying; reporting the reach alone leans on the discipline that failed in the first place.

Whether a tag belongs on a test case as well, replacing the <a data-rel> a case carries today. Two spellings for one idea is the cost, and a test document is HTML where the anchor already works.
