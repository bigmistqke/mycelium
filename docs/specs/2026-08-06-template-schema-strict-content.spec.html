Strict content in the template schema: closing the root and the fields implemented 2026-08-06

The generic validator checks two things about a conforming element. It looks up each declared field among the direct children, and it rejects an undeclared child whose tag carries the family prefix. Everything else passes.

Two holes follow, one at each level.

At the root, a tag without the family prefix meets nothing. A <div> and a <blink> added to a knowledge node validate clean. A census over the 903 instances finds 550 <a data-rel> edges and 22 <script> elements sitting there, and nothing else. So the whole graph structure lives outside the schema, and two live edges carry relations (produced, resolves) that no vocabulary lists.

Inside a field, nothing looks at all. The walk reads textContent for a pattern or an enum and stops. A <b> inside a title is invisible, because textContent flattens it. Every field is unstructured, whether or not that suits it.

Underneath both sits the same cause. Every placeholder in every template is empty, so the shape a template declares is one level deep, and the validator reads shape.children once. Nothing decided against declaring a grandchild; the machinery simply never grew.

Turn the default around. A conforming element may hold only what its template declares, at the root and inside every field alike. The prefix guard goes away, and !allowed.includes(tag) becomes the whole check.

This depends on the cardinality spec, whose repeatable declaration is what lets a template say that a field may hold many of something.

Three kinds of content, measured

A census over the corpus splits every declared field three ways.

25 fields hold text and never anything else, among them knowledge-title at 471 instances, knowledge-confidence at 471 and plan-status at 275. These need no declaration. An empty placeholder already means text.

A second group holds prose that varies: knowledge-detail across 381 instances holds paragraphs, lists, headings, a blockquote and a table, and spec-design holds eight different tags. Listing those is busywork that would need revisiting whenever someone writes a document slightly differently.

A third group holds a nested type rather than content. plan-step holds a title, a status, a detail and a check; test-case holds a name, a status, a script and a fixture. These are the most rigid of the three and the schema currently says the least about them.

The opt-out, for open prose

A placeholder carrying markup may hold any elements at all. It is a permission, and the word says what it permits rather than what it gives up, which is how required, pattern and enum already read.

<knowledge-detail markup></knowledge-detail>

Seven fields take it: knowledge-detail, plan-detail, the four rich fields of a spec, and test-fixture, whose content is whatever the test happens to need.

Declaring a small vocabulary instead

Where a field holds a fixed and short list of tags, declaring them beats the opt-out. language-meaning holds 32 links across 22 instances and nothing else. test-subject holds 5 links and nothing else.

<language-meaning required>
  <a repeatable href=".+"></a>
</language-meaning>

Mixed content needs no rule of its own. The walk iterates elements, so text sitting between them never reaches a check, and a sentence with a link inside it validates as a sentence with a link inside it.

The same form closes the root. Declaring the edge uses the attribute-value-as-pattern rule the schema already has, so one declaration both admits edges and closes the relation vocabulary.

<a repeatable href=".+"
   data-rel="^(depends_on|blocks|supports|contradicts|alternative_to|leads_to|specifies|elaborates)$">
</a>

test.template.html declares its script the same way, copying language-rule, which already carries <script required></script> and proves the form works.

Naming a nested type

For the third group, a placeholder names the template its content follows.

<plan-task repeatable conforms-to="#plan-task"></plan-task>
<figure-node required repeatable conforms-to="#figure-node"></figure-node>

A parent then pulls its children into validation. This says the thing plan.template.html currently records as a limit: that a parent's template can't reach into that child's own internal shape.

It also closes a gap in the figure family. No figure-graph in the corpus declares conformance, so no figure has ever met the generic validator, and a node placed at nowhere validates clean. One graph declaring conformance now brings twelve nodes with it, and no node needs an attribute of its own. See the observation about an instance living inside a host document for the question that leaves open.

What it costs

No document changes at all. Every text-only field already holds text in every instance, every prose field gets the opt-out, and every small vocabulary gets a declaration covering what the corpus already contains.

The work lands entirely in the templates: seven markup markers, eight small vocabularies, four conforms-to declarations, an <a> in four templates and a <script> in one.

Anything about how many edges of which relation a given type should carry. This spec makes a template able to say that a node holds edges and which relations exist. Whether a decision must carry an outgoing edge stays a question for an audit, which sees the whole corpus.

Text-level constraints inside a field, such as forbidding a link in a title while allowing bold. An empty placeholder means text and that is the whole of it.

Repairing the two edges carrying unlisted relations. They fail on the first run after this lands, and fixing them is a separate step with its own judgment about which relation each one meant.

A census records what the corpus holds, not what it should allow. Marking knowledge-title text-only forbids a code span in a title forever, and declaring <p> alone inside language-detail forbids a bullet list there. Nobody has wanted either yet, so each of those is a decision taken from evidence of habit rather than from evidence of need.

Whether markup should constrain anything at all. It currently permits every tag, including a <script> inside a detail field, which would run in a browser.

Whether conforms-to on a placeholder should accept a reference into another template file. test-fixture holds a figure-graph in twelve instances, which is a nested type from another family, and this spec covers it with markup instead.
