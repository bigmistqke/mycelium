A comment earns its place by saying what the code cannot. // Runs from the OS temp dir, not this repository. Loading the project's CLAUDE.md and its MCP servers is most of what made an early version take 14s per call instead of 3s. // Apply edits in reverse order. First we collect the ranges, then we loop backwards over them, then we return the result.

Code already says what it does. A comment repeating that costs a reader twice: once to read it, and again to check whether it still matches.

Four things earn the space. An alternative someone rejected, and why. A constraint from outside the file, such as a format another tool demands. A reason the obvious change breaks something.

A consequence a reader cannot see from here earns it too.

Four things do not. Restating the line below. Narrating the order of operations. Explaining a language feature.

The fourth is leaking the reasoning that helped whoever wrote the code and helps nobody reading it. That one is the common failure and the hardest to spot, because it felt useful at the moment of writing. A working note is not documentation.

Some clutter is not clutter but a decision in the wrong place. A comment naming a rejected alternative is a knowledge-decision that nothing can query, and moving it beats deleting it.

Keep the comment when the call is close. Deleting one that was carrying something costs more than leaving one that repeats the code.
