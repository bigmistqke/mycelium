Fields: a title carrying the principle itself, a confidence, and an optional detail. The title is the axiom, the way a knowledge title is the claim, and the detail holds the reasoning.

Confidence is not decoration here. Someone who commits to a principle and someone who infers one by reading a codebase write the same shape of document, and the inferred one is the likelier misreading.

Composition is a link and nothing else. A subsystem's axiom points up at the general one it narrows, so asking which axioms govern a subsystem walks upward from its own. No region attribute, no scope, no cascade.

 pnpm mycelium validate Declare canon-specification and canon-behaviour completed

A specification holds a title, edges up to the axioms it serves, edges to the documents and source files it describes, and its behaviours. No prose field and no detail field, though every other type in this corpus has one.

Leaving detail out is the load-bearing part. Each kind of content that is not a behaviour already has a family: a criterion is an axiom, an incident is a knowledge node, a word's meaning is a language term, and design reasoning is the design document. A detail field is the hole all four go through.

A behaviour carries an id and one falsifiable sentence. The validator should reject a behaviour holding block-level markup, since a paragraph means a test citing it cites several claims at once.

The id is an author-chosen slug, never a number. A number rots the first time someone inserts a behaviour above it, which the project that ran this methodology before learned from its own numbered axioms.

Same three commands knowledge already carries, for the same reasons. update fills or clears a field on a node that exists, and link upserts on the pair of relation and target, so it can correct a label but never a direction.

unlink is what a mis-aimed edge needs, since running link again leaves a second wrong edge beside the right one. An axiom pointing the wrong way up its refinement chain is exactly that mistake.

No del in this pass. Deleting a specification means dropping every behaviour inside it, and every citation from source pointing at those behaviours stays behind in files this command does not own.

Three audits declared beside the types they check, discovered by the existing crawler with no engine change: grounded, exhaustive, cited. Write the citation reader pending

A citation is @specification, then a path from the repository root, then a fragment, one target per line, inside a comment. Repository-root paths because src/ sits at a different depth from a script block inside docs/, and one target should not need two spellings.

commentRanges in code-comments.ts already returns every comment in a TypeScript or JavaScript source alongside what it sits above, where subject.declares names the kind and subject.name names the thing. So one call gives both the citation and the name of the test carrying it.

Two places hold code, not one. Eight documents in this corpus keep their implementation in a script block, so the reader covers plain source files and script blocks inside documents.

Only a leaf test carries a citation. An enclosing group spans a whole file and answers to no single behaviour, so a citation there means picking a child's target arbitrarily, and an inner group restates what each child already carries.

 pnpm mycelium validate Write grounded pending

Every axiom reaches a behaviour beneath it, and every specification reaches an axiom above it. An axiom with nothing under it is a belief nobody acted on.

Stored edges point up only. A specification names its axioms and an axiom names the one it refines, so the downward reach this check asks about gets computed from those, never authored. A hand-maintained reverse index rots, and a forgotten entry in one looks exactly like an axiom nothing derives from.

The honest cost, which the design states: a broad axiom nobody has read down into a subsystem reaches nothing there, and this check cannot tell that apart from an axiom that does not apply. Writing the reading is the work.

Exhaustive: every behaviour has a test citing it. Cited: every test cites a behaviour. Two directions of one joint, with no exemption on either side, which is what dropping the requirement marking bought.

Cited is the one that closes the loop. A test citing nothing is a claim about the system that no specification makes, so either a behaviour is missing above it or the test checks something nobody meant to promise.
