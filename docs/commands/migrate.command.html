Commands: migrate

Purpose: the one-time moves that turn the knowledge graph into the notebook
Design: the spec for that family
Lifespan: this file goes once the migration lands. It sits in the corpus rather than in a scratch directory so that what it did stays readable, and so it runs through the same engine as every other command.

Why a command and not a script

The migration reads and rewrites the whole corpus, so it parses rather than pattern-matches. Running it through the engine gets that for free: fs.get hands over a parsed document and the engine serialises whatever the command touched, so no rewrite here has to find a tag by searching text.

This project has the scars that argue for it. An anchored regex renamed opening tags and left same-line closing ones, which wrote a mismatched tag into eighty documents. A replace aimed at </body> landed inside a node's prompt, because that prompt quotes markup, and cut a generated page in half.

One process also beats 269. Deleting through knowledge del costs four seconds a node, since each run re-reads every other node to find the edges pointing at it. Doing the same work in one pass takes one traversal.
