Commands: explore

Purpose: whole-docs/-tree commands that don't belong to any one content family — the same reason knowledge generate graph can't be it: that command deliberately only ever looks inside knowledge/, and no single family's own *.template.html is the right scope for something that needs to see knowledge/, specs/, and everything else at once.
Not a template: like template.template.html, this file declares no <template id="…"> and nothing conforms to it via data-conforms-to — unlike it, this one does have commands, which is exactly why it isn't named explore.template.html: that suffix already means "instances conform to this," and nothing does here.
Found the same way as a family template: mycelium run explore <command> resolves through the same <id>.template.html-or-<id>.command.html lookup every other command uses — the engine doesn't distinguish the two once it's found the file, only in what it means for that file to exist.
