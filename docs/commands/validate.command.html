Commands: validate

Purpose: check every document under docs/ against the template it declares conformance to, then run every cross-document audit the corpus declares. The gate the whole corpus rests on, and the one command whose failure means something is wrong rather than missing.
Not a template: like explore.command.html, this file declares no <template id="…"> and nothing conforms to it. It has commands and no type, which is what the .command.html suffix means.
Why a document at all: the engine used to name validate in src/run.ts, dispatching it before it looked for a host file. That reserved the word against every future family and made core name one command it could not read off a document. Declaring it here costs nothing and keeps the engine's knowledge to the protocol alone.

Commands

The work itself lives in src/validate.ts, the same way every other family's commands call into src/. What this document declares is the command, not the implementation.

This host exports a default, so mycelium validate runs with no subcommand after it. Naming one would only repeat the host's own name.
